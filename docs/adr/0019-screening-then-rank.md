# ADR-0019 · 核心循环改成「逐轮二分筛选 → 组内定序」两步

- 状态：已采纳（2026-09-29）；2026-09-29 语义改写（原版「筛选到人数 = 档位」已作废）
- 关联：ADR-0013（导航相位）、ADR-0008（会话模块）、ADR-0015（档位 7/16/40）

## 背景

`core.replay` 的**精确全序**对决是核心循环，代价是手机上的点击量：7 人最坏 14 题、
40 人最坏 177 题（ADR-0015）✓。2026-09 实测（390×844）：对决页整页约 1900px，
**两张脸的顶边在第 840px** —— 手机首屏刚好看不到要选的东西；而真正要决策的两张脸
只占全页 330px ≈ 17% ✓。

交互范式原型（分支 `prototype/ui-v9-duel`）出了四个方向：滑选（无按钮）、
锦标赛（选边不选张，7 人 ~3 题但**精度下降**）、清单标注、对照长条 ✓。用户选 **G 清单**。

## 第一版（已作废）

原决定是「一屏列出档位人数，逐个标留/划掉，**结果人数必须等于档位**」。**实现后发现
它在数据流下不可用**：`session.toggleSelect` 在 `selected.length >= size` 时拒绝
（第 241 行），所以挑人阶段最多只能选到档位人数（7/16/40）；而提交门槛是
`kept >= size`，于是 `kept = 已选 − 已划 ≤ size` → **只有「一个都没划」才可能提交**。
「划掉」的唯一后果是把路走死，零可用结果 ✓。

## 决定

**筛选变成逐轮二分**：用户把名单切成「保留组」与「划掉组」，**保留组必然占据前 K 名**
（她是更想留下的），**划掉组占据后段并仍要排组内名次**。

- **每轮强制划掉保留组的一半**（`floor`）✓ —— 定值门槛，不给「全留」的旁路 ✓。
- **保留组剩 4 人即停**，进入排序 ✓。每轮可主动继续细分 ✓（同一页重复进入）。
- **组内名次全部要排**（保留组与每个划掉组都跑精确全序）✓。
- **层级由内到外填名次**：最内层（最终保留组）= 第 1..K 名；最后一轮划掉的组接在其后；
  越早划掉的组越靠后 ✓ —— 因为「早划 = 更早确认不要」，而后续轮次仍能从中挑人 ✓。

### 各档位的轮次与题数

| 档位 | 轮次（每轮划掉人数） | 各组（内→外）     | 总题数 | 对比全排           |
| ---- | -------------------- | ----------------- | ------ | ------------------ |
| 7    | [3]                  | [4, 3]            | 8      | 14 → 省 6（43%）   |
| 16   | [8, 4]               | [4, 4, 8]         | 27     | 49 → 省 22（45%）  |
| 40   | [20, 10, 5, 2]       | [3, 2, 5, 10, 20] | 106    | 177 → 省 71（40%） |

**省下的是「跨组比较」那一部分** —— 组内比较一个都没省 ✓，这是「定值门槛 + 组内也排」
的直接代价 ✓。7 档 14→8、40 档 177→106 ✓。

## 为什么不是别的

- **结果人数必须等于档位**（第一版）：见上，零可用结果 ✓。
- **换人补位**（划掉 → 回挑人页补一个）：人加回去、题数一分不省，「划掉」仍无正收益 ✓。
- **候选池 > 档位**（7 档可挑 10 再筛 7）：要引入「候选池上限」新概念，托盘的 `7/7`
  变成 `12/7`、档位 chip 全部重写、40 档要选到 43 人 ✓ —— 为一个筛选页付这么大代价 ✓。
- **档位变「至少 N」**：「神7」选出 5 个人自相矛盾 ✓。
- **划掉组不排组内名次**（按划掉顺序倒序填）：能省更多题，但海报有近半格（40 档 20 格）
  是任意顺序 ✓ —— 与「精确全序」的既有设定冲突 ✓。
- **可递归但不设下限**：分到每组 1 人时**1v1 一次都不发生**，对决页消失 ✓。

## 后果

- **档位语义被保住**：选人阶段的硬上限仍是档位人数（`toggleSelect` 不变 ✓），
  结果人数恒等于档位 ✓ —— 只是名次由「筛选层级 + 组内对决」共同决定 ✓。
- **排序步零改动**：`duel_saved` / `duel_extra` / `undo` / `duel_leave` 全部继续使用 ✓；
  `duel_intro_*` 与 `duel_title` 改写成新语义 ✓。
- **相位增加**：`core.nav` 的转移表要认识「筛选」（`screening` ✓）—— 挑人页与对决之间的
  一站，独立可续玩 ✓。
- **`worstCase` 从「人数的一个函数」变成「组大小的求和」** —— 题数上限不再只由档位决定，
  由**筛选到哪一轮**决定 ✓（保 4 人就停 vs 继续细分，题数不同 ✓）。
- **划除按轮次持久化**：`cut` 从「平面 id 列表」变成**按轮次分组的数组** ✓
  （名次由层级决定，所以轮次顺序是数据的一部分 ✓，不是实现细节 ✓）。
- **跨组比较被禁止**：组内对决不得拿另一个组的人做对手 ✓ —— 否则「保留组占据前 K 名」
  会在后续题里被推翻 ✓，语义自毁 ✓。
