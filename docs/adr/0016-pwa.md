# ADR-0016：做成 PWA（可安装 + 完全离线），安装入口放页脚

日期：2026-09-28

## 背景

站点是纯静态、无运行时接口的：成员数据全在 `members.js`（376KB），逻辑代码合计约 500KB，图片 85MB（`img/full` 68M + `img/thumb` 17M，1375 人 ×2）。也就是说**壳与数据加起来只有约 540KB，完全可以整体装进浏览器**——这个体量以前一直是个"网页"，而它真正的用法是地铁上掏出来挑脸。

现状确认（实测）：无 `manifest`、无 `sw.js`、无任何图标链接（浏览器标签页是默认地球图标）。

## 决定

1. **可安装 + 完全离线**：新增 `manifest.webmanifest` 与 `sw.js`。
2. **壳走 network-first + 缓存兜底**，不 cache-first、不设需要人工改的 `CACHE_VERSION`：本站没有构建步骤，忘了改版本号就会让用户长期吃旧壳；代价只是在线时每次开页多一个往返（小站，几十毫秒）。离线时用缓存 → 秒开。
3. **图片 cache-first + FIFO 封顶 600 条**：图片 URL 永不失效，命中即对；封顶防涨到 85MB。**不预缓存图片**（装不动）。没缓存过的成员离线时显示占位图。
   - 封顶按**条数**计，而名册用 thumb（约 10KB）、对决卡与海报用 full（约 50KB），一次完整对决每人吃两条 → 600 条实际覆盖约 **300 人**，最坏约 30MB。这是接受的边界：翻回去看很早浏览过的人可能变占位图。
   - 配套一条：**选中成员时顺手预热 `img/full`**（`warmPhotos()`，经 SW 的 image cache-first 落盘）。没有它，装到桌面后离线做的那张海报只有底色和字——海报与对决读 full，名册只用到 thumb。
4. **字体**：Google Fonts 的 CSS 与 woff2 走运行时 cache-first；**接管之后**（`warmFonts()`，挂在 `controllerchange`）把 CSS（CORS 可读）与其中解析出的 woff2 重新请求一遍。首访的字体请求发生在 SW 接管之前、不进缓存——只做「不预缓存 + 运行时缓存」的话只有第二次访问后离线才有原字体（实测断网后 `document.fonts.size` 0、`h1` 宽 140.3 而非 160，字形明显变样）。
5. **更新流程不自动 reload**：新 SW 就绪时显示顶部非阻塞横幅「有新版本，刷新后生效」+「刷新」，页面在用户点之前不跳。绝不能自动 reload——用户可能正打到第 12 题。
   - 实现上让新 SW 在 `install` 里直接 `skipWaiting()`，页面只负责决定何时 reload。**原方案是「waiting + postMessage 让它 skipWaiting」，实测那条路不可靠**：消息发给 waiting 里的 worker 收不到（发给 active 的能收到），`skipWaiting` 永远不发生，点了「刷新」没反应。壳是 network-first，SW 提前激活对用户不可见。
6. **安装入口放页脚**（`colophon` 内一条虚线框：安装 + 「iOS 怎么装？」）。四版原型（页头按钮 / 底部安装条 / 流程内引导卡 / 页脚入口）里选的 D：不新增常驻表面、零版面代价。**代价是发现率低**（真站名册 1375 人，页脚在很下面），本条接受该取舍。
   - **修正（第二轮，用户报「底部没看到安装按钮」）**：最初把整行的出现吊在 `beforeinstallprompt` 上，于是 Firefox / macOS Safari / headless / 非安全上下文里入口彻底消失。现在：**除已装成应用（`standalone`）外始终显示**；有没有一键安装只决定「安装」按钮的行为（能一键就一键，不能就打开指引）。
   - 教训：把「能力探测」和「入口可见性」绑在一起，等于把可用性押在探测事件一定来；后者应当是无条件的前者。
7. **离线指示**：页头一枚小胶囊（离线时才出现）。
8. **安装指引浮层**：按平台分支渲染（iOS「分享 → 添加到主屏幕」4 步 / Android「菜单 → 安装应用」3 步 / Mac「文件 → 添加到程序坞」3 步 / 其他 3 步，其中明说桌面 Firefox 不支持、应用商店式安装请换 Chrome/Edge）。非安全上下文（http + 局域网地址）额外显示一句「装不了、也不能离线，请用 https 或 127.0.0.1」。
9. **图标**：`scripts/make_icons.py`（Pillow）生成 192 / 512 / maskable 512 / apple-touch 180 / favicon 32，产物提交、脚本留档；标记是系列中立的粉色底 + 白色「7」+ 柠檬黄下划线（三系列共有的是「7」：神7 / 7福神 / 推し7）。

## 后果

- 顺带修一个**既有缺陷**：`document.fonts.load()` 在取不到字体时会 reject，一路冒泡让 `drawPoster()` 断掉——离线且字体子集没缓存时，海报画布一直是空的。现在吞掉该失败（字体没加载出来也要出图，只是字形退化）。

- 缓存了壳 = 离线可完整走完挑人 → 对决 → 出图；已浏览过的成员离线也有照片，**选过的人离线也有海报照片**（靠第 3 条的预热）。
- **混合版本的窗口**：壳走 network-first 且没有构建步骤，理论上某次部署后「首次离线冷启动」可能拿到新 `index.html` + 旧 `app.js`。表现是降级（新键不生效、新表面缺失）而非崩溃，点一次「刷新」自愈，故接受。
- **`sw.js` 的 `VERSION` 只是缓存名常量**，生产不手改（改一次会把图片缓存整批作废）；它存在是为了让 E2E 能在临时副本里模拟一次升级。
- `meta description` 与 manifest 描述补等爱系列与「推し7」；档位口径保持 **7 / 16 / 40**（ADR-0015 已下线 32）。
- Service Worker 只在安全上下文注册（HTTPS 或 `localhost`/`127.0.0.1`）；`file://` 下不注册（本来也打不开海报导出）。
- 新增测试缝：预缓存清单与盘上文件一致（node:test，产物不变量缝的延伸）、断网重载黑盒（E2E）。
