# ADR-0023 · 照片冻结：增量跑只解析缺图者，源变好靠显式刷新

- 状态：已采纳（2026-10-05）
- 关联：ADR-0022（照片身份判定）、`docs/agents/data-pipeline.md`、`CONTEXT.md`（增量跑 / 全量刷新）
- 依据：fetch 管线与 E2E 耗时的四轮 grilling（2026-10-05）

## 背景

管线的耗时几乎全在**旧站快照扫描**：最多 900 次抓取、每次前 `sleep(1.5)`、全串行 →
光睡觉 22.5 分钟，加 Wayback 真实响应 ≈ **50–100 分钟**。而其中绝大多数抓取服务的是
**已经有站内照片**的成员：它们在上一轮已解析、已下载、已压缩，本轮再解析一遍只是把同一个
结果重算一次（实测：一轮全量跑完，下一轮唯一变化的通常只是个别成员）。

同一批还定了另一件事：E2E 四套件串行 ~25 分钟，改一次 `app.js` 就要等 —— 那是**并行**问题
（见 `.scratch/perf-fetch-e2e/spec.md`），与本文的照片语义无关。

## 决定

1. **增量跑为默认**：照片解析只服务**没有站内照片**的成员 —— 判据是 `img/full/<id>.webp`
   与 `img/thumb/<id>.webp` **都在且非空**（与 `img` 标志同一真值源）。**数据照常抓**
   （官网/维基）：新成员、改名、毕业必须能进来。
2. **全量刷新是显式开关**：`--refresh-photos` 忽略「已有照片」的跳过与 `_resolved.json`
   缓存、为所有成员重新解析照片。`--force` 语义不变（**只重压缩** —— `download()` 命中已有文件即返回，从不重下载；
   usage 里写的就是 recompress）。
3. **跳过不丢尝试**：缺图者（没有站内照片）每轮仍被尝试 —— 源以后出现就能自动补上。

## 理由

- 日常跑从小时级降到分钟级；代价是**照片冻结**：源变好（官方肖像上线、更清晰的照片出现）
  不会自动生效。
- 冻结可接受：照片是**资产**、不是活数据；刷新开关把它变成一次性成本。
- 反面方案（每轮全量重解析）被实测否掉：90% 的抓取服务的是「已经有图的人」。
- 以**站内文件**而非解析缓存为判据：缓存只覆盖早安 loader，且会与文件脱节
  （缓存里有 URL、下载却失败的人会被缓存挡住、永远卡在没图）。

## 后果

- 管线默认**不再升级已有照片**；升级要 `--refresh-photos`（写进 `docs/agents/data-pipeline.md`）。
- `_resolved.json` 的角色缩小：正常增量跑里它不再影响结果（跳过以文件为准），
  只对「有 URL 但下载失败」的人仍有价值（下一轮直接重试下载、不必重解析）。
- 未来加新系列时：新人没有站内照片 → 自然被抓，无需特判。
