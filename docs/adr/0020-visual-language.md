# ADR-0020 · 视觉语言：效率区 / 表现区分区 + 杂志感基调

- 状态：已采纳（2026-09-30）
- 关联：ADR-0014（海报四样式）、ADR-0011（页头横账）、ADR-0016（PWA）、ADR-0019（筛选步）
- 依据：三轮 grilling（12 条决策全采纳）、`prototype/ui-v8-tone` 方向板（用户选「杂志感 + 效率区降密度」）

## 背景

2026-09-30 实测（390×844，classic 皮肤，英文界面，新访客未关引导卡）：

- **第一张成员卡出现在第 738px** —— 视口 844 的 87% 之前全是页头 60 + 步骤条 77 +
  引导卡 + 进度环 + 9 个筛选控件；底部托盘 100px 又盖住它。也就是说新访客的首屏
  **看不到产品本身**。此前 AGENTS.md 写的「首屏见脸」只在**关掉引导卡之后**才成立。
- **没有设计刻度**：14 个字号散着写（12/13/14px 各用 16/16/3 次），正文 15px 偏小；
  间距里 7px / 14px 是刻度外产物。
- **几乎没有动效**：全站 1 个 `@keyframes`（shake）+ 6 条 `transition`；
  微交互 3 个 `:hover`、1 个 `:focus-visible`。
- **三处对比度欠账**：`--muted` 在页底 4.33:1（正文需 ≥4.5）、`--peach` 作正文 3.96:1、
  占位图首字 2.11:1。
- **一个真缺陷**：`.kami` 在窄屏被改成透明无边框 20px，而它的 `::after` 洋红条
  （`--peach` `#e4007f`）定位在 `top:20px`，**压在字面上** —— 两款皮肤下都读作「错位」。

用户要求以 Awwwards / Webby / FWA 获奖级为品质标准。grilling 的第一问就点出这个词
与本站目标的冲突：获奖网站要的是停留与 wow，而本站的成功是「尽快选完 N 个人」
（前三轮刚把页头压到 60px、把对决页压到一屏）。

## 决定

### 1 · 分区：两把尺子，不逼一套标准两处妥协

界面分**效率区**（挑人 / 筛选 / 排序，判据是「一屏做完一步」与「不加装饰」）与
**表现区**（首屏 / 结果页含海报，判据是视觉与动效品质，产物是分享物）。术语进
`CONTEXT.md`。理由：中途那批人要快，而分享海报的人全部落在表现区。

### 2 · 基调 = 杂志感，效率区降密度（**一套基调 + 密度档**）

大字号、大图裁切、圆角 18px + 柔影、主色做整条色带。效率区的密度需求靠**同一套基调
的密度档**满足（间距取小值、字阶取小值、动效取 120ms），**不维护两套基调** ——
两者的差别其实只是密度与圆角，维护两套会让 CSS 面积翻倍。

方向板上另外两版被判否：**编辑感**（细线 + 紧字距）在表现区撑不起「值得截图」；
**工业感**（全 1px 边框 + 2px 圆角 + 主色只做信号）与效率区匹配，但结果页是分享物，
冷淡会直接掉分享意愿。

### 3 · 签名时刻 = 结果页「揭幕」

两张脸合并成一张海报的共享元素转场。判否「对决页翻卡」：40 档要做 106 次翻卡，
会变成噪音。**揭幕仍需用户点「刷新」才切**（见 ADR-0016 的更新流程不变式）。

### 4 · 设计刻度（先立刻度，再改页面）

- **字阶 5 级**：12 / 14 / 16 / 20 / 28；正文 16px 起（15px 在 390px 上偏小）。
- **间距**：4 的倍数（4 / 8 / 12 / 16 / 24 / 32），顺手消灭 7px / 14px 这类刻度外产物。
- **动效**：三档时长（快 120 / 中 200 / 慢 320）+ 一条缓动，全部尊重
  `prefers-reduced-motion`。本轮只实现三个关键时刻：**进场 stagger**（名册卡）、
  **点选反馈**、**切屏转场**；不做编排级时间线。
- **刻度是给新代码的约定，不是硬律**：刻度与窄屏横账冲突时**预算优先**，例外要写明。
  本轮唯一的例外是档位段按钮的横向内边距 `7px` —— `14px` 时英文「Ranked 40」被裁
  78px 且滚动条被藏，改回刻度值会让 en × 贴纸皮 × 40 档差 1px 装不下。
- **刻度守卫是棘轮**：清单外的刻度外值一律红，清单内的**逐项注明归属**，每轮清掉
  自己新引入的那些。既有的全清要连桌面宽度的验证一起做（改 padding 就是改版面，
  而本仓当前的验证面只有窄屏与页头矩阵），属另一轮的工作。

### 5 · 色彩：主色不动，只补中性阶

`--peach` `#e4007f` 已有性格且被**海报令牌等值守卫**逐值绑定，改它会连坐 4 张海报。
本仓的对比度问题不在主色，而在**中性阶太薄**（同一页里白卡、灰底、灰字、灰边全是
手调的相近灰，层次出不来）→ 补齐 6 级中性。判否「换主色」与「加语义色」（当前没有
错误/警告态的界面，语义色没有用途）。

### 6 · 对比度当硬指标，不是观感

正文 / 次要文字 / 图标 ≥4.5:1；**占位图首字 ≥3:1**（套 WCAG 大字阈值）。占位首字是
**信息**（离线时要读得出是谁），不能当装饰豁免 —— 它已经欠了很久，且上一批把它的
曝光面放大到了 96px × 四样式 × 三档。

### 7 · 皮肤：classic 升到该水准，贴纸皮只保证不破

守卫要求两块令牌**键集相同**（`test/style-artifact.test.js` 已自动化）。用户主用一款，
两套都升等于工作量翻倍；合并成一套会杀掉「皮肤」这个已记录的能力（ADR-0014），
而它是本站少见的趣味点。

### 8 · 断点保留，横账预算变成可测脚本

容器查询（`@container`）被判否：它擅长**单组件**响应，而本站的硬约束是**跨组件加总**
（页头 = 品牌 + 系列 tab + 「更多」三个组件凑一行），容器查询解决不了加总。
改为保留 560/380/340 三个断点，但把「每个断点的横账预算」变成运行时可测的脚本
（`/tmp/opencode/verify-header.cjs` 那类），AGENTS.md 只指路。
**注意「数字由测试钉住」这半句的现实**：仓内（缝③）只能守**形状**（规则不许被删），
守不住预算 —— 预算数字活在仓外脚本里，会话结束就没了。所以仓外的量法要连同
**结论数字**一起写回工单，那才是下一个会话能读到的。

### 9 · 首屏 738px 的两个元凶

引导卡压成**一行细条**（正文收进原生 `<details>`，点「?」就地展开）；工具条一行只留**档位段 + 「筛选」按钮**，其余 6 件（状态/团体/期生/搜索）进按钮开的面板。
判否「只留标题一句话」——筛选行仍占约 90px，第一张脸进不了第一屏。

**判据的适用范围**：本 ADR 说的「一屏见脸」按 **390px 及以上**成立。≤380px 时页头
换行到两行（多 47px：品牌 + 三个系列 tab +「更多」在 343px 内装不下，中文差 5px、
英文差更多），第一张成员卡落在 432px。窄设备那一档**尚未解决**，要单独一轮：
要么继续压横账，要么接受两行页头换那 47px。各宽度的实测表在工单 02。

## 代价与被记录的冲突

- **令牌等值守卫为视觉让步到什么程度**：视觉改造必然改令牌值，而守卫要求
  `poster.js` 的内置兜底与 CSS 逐值相等。处理办法是**两边一起改**（兜底就是「另一套
  皮肤」的替身，不改就等于给无 DOM 场景留了第三套外观），守卫继续有效。
- **贴纸皮不升**：它会与 classic 拉开差距。可接受 —— 它是「换个心情」的变体。
- **E2E 几何断言会红**：页头 66/60、托盘 81/84、第一张脸 641/648 等基线是「行为不变」
  的硬验收，视觉改造必然改变部分数值。处理办法是**逐条说明为什么变**，而不是放宽判据。
- **正文 15 → 16px 会让窄屏横账更紧**：页头预算必须重新量（这是第 8 条的直接后果）。

## 被判否的选项（避免以后重提）

- 全站重做到获奖级（含海报四样式与两款皮肤同时升）—— 一次拖下守卫、海报、皮肤三样。
- 维护两套基调（效率区工业感 / 表现区杂志感）。
- 用容器查询替换全局断点。
- 对决页手势加速（左右滑选）—— 新能力，且手势与「撤回」语义会打架，该单独决策。
- 合并成一套皮肤 + 强调色开关。
