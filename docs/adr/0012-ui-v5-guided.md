# ADR-0012：交互方向 v5 · 向导模式（三步指示器、引导、进度与续玩）

日期：2026-09-28

## 背景

现状复核发现五处交互/UX 痛点：① 首屏零面孔（默认全部团体 = 7 个折叠行，要点三层才见第一张脸）；② 选人进度只在托盘；③ 检索只有搜索框 + 团体下拉；④ 对决只有点击，长流程「虽自动保存但不可见」，续玩入口不存在；⑤ 卡片「i」26px 低于触控标准。

据此做了四方向原型（`prototype/ui-v5-interaction` @ `3e21b26`，单页 `?variant=`）：A 向导模式 / B 对决驾驶舱 / C 选人工作台 / D 手势卡组。用户选定 **A · 向导模式**。

## 决定

1. **落 A 的交互集合**：常驻三步指示器（挑人 N/M → 对决 → 出图）、首屏自动展开第一团体 + 第一期生、可关闭的引导卡、选人进度环 + 团体覆盖、选满/半程里程碑、对决首题说明卡、对决常显「进度已自动保存」、续玩卡（继续/放弃）。
2. **导航语义**：新增视图状态 `view`（pick/duel/result），与 session 相位解耦——**① 从对决返回挑人页不丢进度**（保留对决，显示续玩卡）；任何改选（toggleSelect）按既有 session 语义清掉对决；「放弃」显式丢弃。从结果页点 ① 仍是重新选人（对决已完成，丢弃）。
3. **引导只教一次**：引导卡与对决说明卡各自持久化（`akb:coach:v1` / `akb:duelintro:v1`），关闭后不再出现；说明卡只在**新开**对决时出现，续玩不出现。
4. **不做**：B/C/D 的交互机制（时间线回退、拖拽作答、三栏工作台、手势长按）不折入；卡片「i」触控目标本轮不放大（记入遗留）。

## 后果

- `app.js` 引入 `view` 状态与步骤条渲染；`index.html` 新增步骤条、引导卡、进度卡、续玩卡、对决说明浮层；`style.css` 新增对应组件（两套皮肤共用令牌）；`i18n.js` 约 20 个新键（zh/en）。
- E2E 扩展：步骤条状态与导航、① 保留对决、首屏见脸、引导卡持久化、进度环/里程碑、说明卡一次性与续玩卡。
- 原型全套留在 `prototype/ui-v5-interaction` 分支作一手资料；主仓只留胜者。
