# 评审规则（两轴审查时的硬性检查项）

这些是**判断类**规则（没有守卫能替代），评审 agent 在 Standards 轴逐条核。机械类规则已经变成守卫（见
`test/e2e-source.test.js`、`test/style-artifact.test.js` 等），不在这里重复。

来源：各轮 retro 的候选落地（每条附当轮的真实事故，改规则时先读事故）。

## 1. 新工具的 selftest 必须覆盖退化路径

「没有工作可做」与「坏参数」是最容易假绿的路径。实例：`e2e:all` 的 `--max-parallel` 缺值
→ `Number(undefined)` = NaN → 0 个 worker → 打印「0/0 通过」并 **exit 0** —— 把失败记成了通过。

## 2. 性能声明要交替 A/B，跨轮数字不算证据

同一台机器、同一天，网络/负载能让同一阶段差 2–4 倍（实测：管线数据阶段 12.6s vs 65.9s）。
实例：Wayback 并发第一次 A/B 得出「2 并发慢 2.5 倍」，交替跑两轮才看出 2 并发其实最快
（5.9/6.5s vs 串行 13.6/31.2s vs 3 并发 24.5/41.2s）。**结论必须来自同一输入上的交替对照。**

## 3. 生产代码里给测试用的模块级开关，要能保存/恢复

模块级全局会跨测试模块泄漏（同进程按字母序跑时踩到）。实例：`fetch_pool.INTERVAL_SCALE`
（生产 1.0 / 测试 0）把后跑模块的间隔断言搞红 —— 用 `addCleanup` 显式恢复，或优先用注入参数。

## 4. 等待失败必须出声（可以失败，不可以沉默）

任何「等一等、失败就继续」的地方都要留痕。实例：主套件 21 分钟里 18 分钟是 9 次
`ready()` 各烧满 120s 超时（条件恒假），而 `.catch(() => {})` 把超时吞掉 —— 不报错、不失败，
只是安静地烧，最后被归因成「机器慢」。机械守卫在 `test/e2e-source.test.js`；生产管线里
的等价物（`except: continue`、把失败记成「没有」）同样要留痕。

## 5. 长跑命令走后台，不 sleep 轮询

harness 支持后台任务 + 完成通知；`sleep N; tail` 轮询既费回合又容易错过真正的输出。
需要「它还在动吗」的信号，先给命令加进度输出（阶段行 + 心跳），而不是从外面看进程。

## 6. 视觉/像素结论同条件 A/B，数字必须带条件

跨轮数字不是证据（与第 2 条同族，补视觉版）：旧值要**用同一脚本、同一天、同一条件**
实测（`git checkout <旧提交> -- <文件>` 换旧实现再跑一遍），并注明条件（语言 / 皮肤 /
档位 / 字体是否就绪）。实例：把「7 档槽位高 37px → 38px」记成「布局模式差异」——
真因是**字体加载前后按钮宽 97.5↔94**；「托盘 244/600」与「101/97/97」是两组条件混比。
两处都被审查者抓出。
