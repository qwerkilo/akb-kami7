# 02 · 早安 loader 的 parse 纯函数（Wikipedia 两表 + 官网详情页）

- **Status**: ready-for-agent
- **Blocked by**: 无
- **所属 spec**：`.scratch/morningmusume/spec.md`
- **缝**：① Python 解析纯函数（`scripts/test_morning_members.py`，fixture 驱动）

## 内容

**不能复用 `parse_wiki_members`** —— 实测套上去得到 0 人。硬性差异：

| 等爱 parser 的前提                         | 早安 wikitext 实际                                                                      |
| ------------------------------------------ | --------------------------------------------------------------------------------------- |
| 块里必须有 `{{生年月日と年齢`              | 写成 `1999年{{Display none\|0}}10月{{Display none\|0}}7日{{Center(…)}}`                 |
| `from` 格以 `[都道府県]$` 结尾             | `{{Display none\|しずおかけん/}}[[静岡県]]`，整格被模板包                               |
| 按 `\n\|-` 切块后逐块解析                  | 有 `rowspan="2"`（加入期/加入日合并），逐行切会**串行**（实测把某人的出身地当成了姓名） |
| 毕业日取第一个 `\d{4}年\d{1,2}月\d{1,2}日` | 该列先出现「卒業・脱退日」再出现括号里的「発表日」，同行还有加入日                      |

要写的纯函数（网络经注入的 fetch，测试离线）：

1. **拆块要处理 `rowspan`** —— 不能按 `\n\|-` 盲切。这是与等爱最本质的差异，
   先写一个能复现串行的红测试再改。
2. `加入期` 两种写法混用（`{{Center|12期}}` 与裸 `1期`），两种都要认。
3. **剥噪声**：`{{Display none}}`、`{{Efn2}}`、`<ref>{{Cite web…}}`（整个条目 105 KB）。
4. `ニックネーム` 一格可能多行（`ちぇる<br />のなちゃん`）：**第一个用于显示，
   其余留作别名**进 haystack（grilling R1-Q3）。
5. 官网详情页的字段映射**沿用等爱的 `DETAIL_MAP` 思路**，但早安**没有**星座与身高
   —— 不要留空键（grilling R1-Q4）。
6. 状态来自「在现役表还是在毕业表」，**不引入第三个状态**（grilling R1-Q2）。
   「卒業」与「脱退」两种措辞都归 `former`，在注释里记下这个映射的取舍。
7. 假名形如 `{{Display none\|のなか みき/}}[[野中美希]]<br />{{Small|（のなか みき）}}`，
   等爱是从假名列抓的，早安没有那一列，要从这类模板里剥。
8. **`リンリン` 要专门覆盖**（调研里它没被自动抽取认出来，是个人工核对项）。

## 验收

- `scripts/test_morning_members.py` fixture 驱动、**全程离线**。
- fixture 取自真实的 wikitext 片段（存进仓库，就像等爱那批 fixture 一样），
  覆盖：现役行、毕业行、`rowspan` 合并行、多行昵称、`{{Center|12期}}` 与裸 `1期`、
  带 `<ref>` 噪声的行、リンリン。
- **变异验证**：至少五个（去掉 rowspan 处理 / 只取第一个昵称 / 不剥 `{{Display none}}` /
  把 `脱退` 当成 current / 丢掉某个字段），全部会红。
- 至少一条测试断言「早安的 wikitext 用等爱的 parser 得到 0 人」—— 把这次踩过的
  坑钉住，防止有人后来「顺手复用」。
