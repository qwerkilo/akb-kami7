# 06 · 收口守卫与整体验收

- **Status**: ready-for-agent
- **Blocked by**: 04、05
- **所属 spec**：`.scratch/morningmusume/spec.md`

## 内容

把散在各工单里的守卫与整体验收收在一处，**并补上这一批特有的两个缺口**：

1. **「成员不重叠」守卫**。ADR-0021 说重叠是本站**不会报错**的隐患（同一个人在两个
   系列里各有一份档案，只能靠人发现）。所以加一条产物测试：
   **跨系列不得有重名成员**。等爱与早安现在没有交集，但这条守卫是为了**下一个系列**
   —— 它是 ADR-0021 的自动化兑现。
2. **`fetch_members.py` 的键名纪律**。`AGENTS.md` 记着：持久化键名只有一处
   （`core.js` 的 `PREF_KEYS`），`app.js` / `session.js` 不得出现 `akb` 开头的
   字面量。加了第四个系列后要确认**按系列的存档键**自动覆盖到早安
   （`PREF_KEYS` 的 `state: (s) => ...` 应当按系列 id 生成，所以**不该**有任何
   改动 —— 但要有测试证明它）。

## 整体验收清单

- `npm run check` 全绿（prettier + 全套测试）
- 回归 E2E / v5 / PWA 三套全绿
- 复杂度棘轮未推高；若 `names()` 改成查表，**应该降**（当前它在 CCN>10 的名单边缘）
- 版式基线不动（页头 66/60、首卡 ≤400、托盘不透明、窄屏无横向滚动）
- **缺图名单如实记账**：抓到几个人、哪几级回退失败、有没有继续挖的价值
- `docs/agents/data-pipeline.md` 与 `CONTEXT.md` 与实现一致
- 检查点记一条（基点 = 本批第一个提交）

## 验收

- 两个新守卫各打至少两个变异，全部会红
- 三套 E2E 的「切系列」流程覆盖四个系列
