# 工单 10：下载/压缩失败也要进「为什么没有照片」的汇总

- **Status**: resolved
- **Blocked by**: 无

## 背景（工单 09 真实跑时发现的口径缺口）

管线末尾打「7 位成员没有照片」，而工单 09 的「照片未解析到 N 人（原因）」只列 5 人 ——
差的 2 人（有原栞菜 / 梅田えりか）是**解析到了 URL、但下载/压缩失败**：
日志里逐人可见（`下载失败，跳过 …404` / `compress failed 梅田えりか cannot identify image
file …jpg`），但**没进汇总**。读汇总的人会以为 7 人都是「源里没有」。

## 决定（待拍板）

1. `download()` / `compress_members()` 把失败记进一个 `failures` 列表（`file` → 原因），
   与 `urls` 同生命周期（在 `main` 里收集）。
2. 末尾汇总分两段：**未解析到**（工单 09 的原因表）+ **解析到但取不下来**（本工单的原因表），
   两段的并集 = 缺图名单。
3. 判据：造「URL 404」与「文件不是图」两个夹具 → 两人的名字出现在第二段（不是第一段）；
   既有缺图名单不变。

## 实现记录（2026-10-06）

- `download_all` / `collect_paths` 收 `failures`（id → 原因）：`下载失败`（细节 404/521
  留在 download 的日志行）。
- `compress_members` 收 `failures`：`源图过小（占位图）` 与 `文件不是图（异常类型）`。
- `warn_missing_images(members, failures)`：缺图名单之后补一段
  「照片解析到了但取不下来 N 人（原因）」逐人一行；`main` 里 `failures = {}` 串起
  collect → compress → warn。
- 测试 +3（下载失败记录 / 压缩失败记录 / 汇总含原因）；一条期望值按纪律修正
  （实现带异常类型，断言前缀）。

**真实跑验证（2026-10-06，exit 0）**：

```
warning: 7 位成员没有照片（界面显示占位）：福田明日香、…、有原栞菜、梅田えりか、小数賀芙由香
照片解析到了但取不下来 2 人（原因）：
  有原栞菜：下载失败
  梅田えりか：文件不是图（UnidentifiedImageError）
```

- 与工单 09 的「未解析到 5 人」并集 **5 + 2 = 7**，正好等于缺图名单（判据 ✓）。
- 产物照片集合不变：1544 人 / 1537 有图 / 7 缺图。
- 复杂度棘轮抓到 `compress_members` CCN 11 → 抽 `_record_failure` 归位；变异 2/2 被杀。

## 注意

- 本工单只改**怎么描述**，不改重试/下载策略（那是另一个决定）。
- 「文件不是图」的根因已查明（2026-10-06）：不是 404 页被当图 —— 是**图片本身从未被
  Wayback 收录**（CDX 查 `cute01_s.jpg` **0 行**），`id_` 重放于是回一个错误页
  （72KB HTML）；而传输层有时把这个错误页 **gzip** 压缩（15335 字节、头 `1f 8b`）→
  被当二进制存进 `_orig`，永久卡住。已修：`wiki.maybe_gunzip` 在取数出口解 gzip
  （JPEG/PNG/WebP/HTML/JSON 都不以 `1f 8b` 开头，判据安全；坏 gzip 原样返回）。
  两个 ℃-ute 人（有原栞菜 404 / 梅田えりか 错误页）的图**源里确实没有** ——
  Commons 与 /og/ 都已试过，是真实上限。
