# 工单 09：照片源的「没找到」要说清是哪一种

- **Status**: ready-for-agent
- **Blocked by**: 无

## 背景（两轴审查的两条发现）

审查 `fae19a5..b5f141a`（早安照片批）时抓到两条同族问题：

1. **「源里没有」被写成事实，实际只是「本轮没扫到」**：`issues/03` 的残留 12 人写
   「都是源里确实没有可用照片」，但同一批源在后来的跑里又找回了 **5 人**
   （八木栞/石栗奏美/田代すみれ + 小川紗季/前田憂佳）—— 当时旧站扫描按 URL 记账、
   撞了全局上限 900，排在后面的团（つばき/OCHA）没扫完。**结论是预算截断的产物，
   不是源的性质。**
2. **「查不成」与「源里没有」被吞成同一种**：`_search_hits` / `_imageinfo` 任何异常 →
   空结果 → 残留原因表写「Commons 无本人文件」（`docs/agents/data-pipeline.md:12`
   早写过这个坑：429 会被记成「源里没有照片」）。

## 决定（待拍板）

1. **扫描完成度**：`_resolve_old_site_groups` 记录每团的「预算是否用完」——
   某团预算用尽（`group_fetched >= budget`）时，该团的残留者原因标「本轮预算内未扫完」，
   不写「无其页」。整轮结束打一行汇总。
2. **失败与空结果分开**：`commons_search_photo` / `commons_photo` 把「请求失败」与
   「查了但没有」分成两种返回（或抛/带标记），残留原因表据此分栏；失败者下轮仍会重试。
3. **同字同名不可区分**（写进 ADR-0022 的补充 + `CONTEXT.md` 的 _Avoid_）：
   子串校验挡得住「村上愛 vs 村上恵」（不同写法），挡不住同写法的两个人；
   `commons_photo`（条目首图）路径更弱（无姓名校验）。要更严就得要求姓名出现在
   **文件标题**（而非描述）或交叉核对分类 —— 这是覆盖率的取舍，先记录、不偷偷放宽。

## 判据（可证伪）

1. 造一个「某团预算用尽」的夹具 → 该团残留者的原因**不出现**「无其页」字样（红/绿可辨）。
2. 注入一个抛异常的 fetch → 该成员的原因标「查询失败」而非「没有照片」；下轮（fetch 恢复）
   能被重新解析（缓存/跳过不挡它）。
3. 同字同名的两条测试（同写法 + 跨界拼接）钉住当前行为（拒绝不了 → 必须显式记录为已知限制，
   测试名里写明）。
4. 变异 ≥2 全杀；不改变既有产物的照片集合（本工单只改「怎么描述」，不改「选哪张」）。
