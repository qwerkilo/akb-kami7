# 工单 03：E2E 进度（块头 + 长等待）

- **Status**: ready-for-agent
- **Blocked by**: 无

## 目标

E2E 跑起来能看出「到哪了 / 是不是在等」，而不是长时间静默：

1. `e2e.cjs` 的 24 个功能块：每块开头一行 `[块 N/24] <名字>`（从既有 `// --` 注释取名字）。
2. **超过 5s 的等待**打一行进度（`…等待字体预热 12s`，每 5s 续报一次）：
   至少覆盖 `e2e-pwa.cjs` 的三处轮询（img/full 预热、字体预热、脸部取样）与 `ready()`。
3. 输出要**实时**（不因重定向到文件而整块缓冲 —— 用 `process.stdout.write` + 显式换行，
   或确认 node 对文件的重定向是行缓冲）。

## 判据（可证伪）

1. 跑一次主套件，输出里能看到全部块头与（若发生）长等待行。
2. 一次 pwa 跑的输出里，预热等待过程可见（不是一条静默的 30s）。
3. check 数不变（245 / 54 / 43 / 72）且全绿。

## 实现记录（2026-10-05）

**实现**：`e2e/_progress.cjs`（`blockStarter` / `waitTicker` / `elapsed`，都只在 ≥5s 时
才开口）；`e2e.cjs` 23 个块头 + 每行 check 前打累计时间线 + `ready()` 心跳；
`e2e-pwa.cjs` 每行 ok/FAIL 打时间线 + 三处轮询（img/full、字体、脸部取样）加心跳。

**画像（主套件实测 21m07s / 245 全绿，2026-10-05）**：

| 块                                                          | 耗时        | 说明               |
| ----------------------------------------------------------- | ----------- | ------------------ |
| 1 首屏                                                      | 126s        | 含一次 `ready()`   |
| 2–10                                                        | 各 ≤15s     | 共 ~36s            |
| 11 单团神7 / 12 v2 选人 / 13 ADR-0019                       | 各 127–132s | 各含一次 `ready()` |
| 14–16                                                       | 各 ≤11s     |                    |
| 17 清空已选 / 18 等爱 / 19 皮肤 / 20 海报像素 / 21 海报样式 | 各 122–134s | 各含一次 `ready()` |

**画像的决定性发现**：心跳 207 条**全部**是 `…等待图片/字体就绪`；9 次 `ready()` 的完成
耗时**全是 120s**（= 超时上限）—— 即每次都在烧超时。根因是名册的 `<img loading="lazy">`
在视口外永不加载、`every(complete)` 恒假。**18 分钟 = 整套的 85%**，白等。
→ 已开**工单 07** 修它（实测主套件 21m07s → 3m02s）。

**这一单的价值**：没有块头与心跳，这个恒假等待不可能被发现（它不报错、不失败，
只是安静地烧超时 —— 之前 21 分钟的套件被归因成「机器慢」）。

## 注意

- 与工单 01 的分工：**本工单管脚本内部**的进度；runner 的「每套件一行 + 失败聚合」在 01。
- 长等待行不要刷屏：5s 起报、之后每 5s 一行。
