# 工单 06：管线并发 + 限流（确定性）

- **Status**: ready-for-agent
- **Blocked by**: 04

## 目标

旧站快照扫描（全量时最多 900 次抓取、串行 + 每次 1.5s 节流）改为**小线程池 + 按主机限流**：

- Wayback（`web.archive.org`）：**3 并发 / 最小间隔 0.5s**；
- Commons（`commons.wikimedia.org`）与 ja.wikipedia：保持 **1 并发 / 1.5s**（429 前科）；
- 429/521 时**自动降速**（间隔翻倍）并重试，封顶后放弃该条；
- 结果按**确定性顺序**应用（同一成员有多个候选时，与串行结果一致 —— 先到者胜要可复现）。

## 判据（可证伪）

1. **全量扫描实测 ≤ 串行的 1/3**（串行基线：900 次 × (1.5s + 网络) ≈ 50–100 分钟）。
2. **结果与串行一致**：同一 fixture（注入的假 fetch + 假 CDX 响应）下，`urls` 与串行版**逐键相同**
   （尤其同一成员多个候选、同一 URL 多个时间戳的情形）。
3. 限流器有单元测试（注入时钟）：间隔不足时排队、429 后间隔翻倍、成功后退回。
4. 变异验证 ≥2 全杀（例：把限流器换成无间隔 → 测试应红；把确定性顺序换成「完成即写」→
   判据 2 应红）。
5. 不触碰其他段（48pedia/官网详情/维基照旧串行）——本工单只并发旧站扫描。

## 注意

- 并发**只对 I/O 等待**有效；解析与压缩是 CPU 侧，保持主线程串行。
- 结果写回要防竞态：worker 只**收集**（`(成员, url, 证据)`），应用顺序由主线程按确定性规则决定。
- 与工单 05 的心跳配合：心跳要能报「在飞 N 条、已完成 M 条」。
