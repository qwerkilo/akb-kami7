# 工单 06：管线并发 + 限流（确定性）

- **Status**: resolved
- **Blocked by**: 04

## 目标

旧站快照扫描（全量时最多 900 次抓取、串行 + 每次 1.5s 节流）改为**小线程池 + 按主机限流**：

- Wayback（`web.archive.org`）：**3 并发 / 最小间隔 0.5s**；
- Commons（`commons.wikimedia.org`）与 ja.wikipedia：保持 **1 并发 / 1.5s**（429 前科）；
- 429/521 时**自动降速**（间隔翻倍）并重试，封顶后放弃该条；
- 结果按**确定性顺序**应用（同一成员有多个候选时，与串行结果一致 —— 先到者胜要可复现）。

## 判据（可证伪）

1. **全量扫描实测 ≤ 串行的 1/3**（串行基线：900 次 × (1.5s + 网络) ≈ 50–100 分钟）。
2. **结果与串行一致**：同一 fixture（注入的假 fetch + 假 CDX 响应）下，`urls` 与串行版**逐键相同**
   （尤其同一成员多个候选、同一 URL 多个时间戳的情形）。
3. 限流器有单元测试（注入时钟）：间隔不足时排队、429 后间隔翻倍、成功后退回。
4. 变异验证 ≥2 全杀（例：把限流器换成无间隔 → 测试应红；把确定性顺序换成「完成即写」→
   判据 2 应红）。
5. 不触碰其他段（48pedia/官网详情/维基照旧串行）——本工单只并发旧站扫描。

## 实现记录（2026-10-06）

**实现**：

- `_old_site_candidates`：16 个前缀的 CDX 查询并发（`fetch_pool`，host=web.archive.org），
  按前缀原顺序归并（确定性）。
- `_pick_old_site_group` 拆成 `_scan_tasks`（按预算展开 (原页, ts) 任务表）+ 并发抓取
  （`raise_first=False`：单张失败跳过、继续别的候选，与串行一致）+ `_apply_scan_pages`
  （**按任务顺序**应用配对：同一成员多个候选先到者胜）。
- `fetch_pool` 新增：`raise_first=False`（失败的键在结果里是异常对象）、**自适应降速**
  （429/521/503 → 该主机间隔翻倍、封顶 5s）、模块级闸门（降速要跨调用保留）+ `reset_gates()`。

**测试**：`ScanConcurrencyTests` 2 条（URL 序靠前的候选先应用；单张快照失败跳过不致命）

- `test_fetch_pool` 3 条（raise_first=False、penalize 翻倍封顶、429 后同主机下次要等
  翻倍间隔 —— 全程假时钟）。变异 2/2 被杀（反转应用顺序 / 去掉降速）。

**如实记账**：`ScanConcurrencyTests` 是先实现后写测试（没先看红）—— 补了变异验证
确认它们承重（反转顺序会被杀）。

**实测（2026-10-06）**：

两次整轮跑的**数据阶段**差了 2–4 倍（同一天：48pedia 来源页 12.6s vs 65.9s），
跨轮比较说明不了并发收益 —— 于是做了**交替 A/B**（同一批真实快照 URL，控制网络漂移）：

| 跑法（8 个快照 URL） | 第 1 轮  | 第 2 轮  |
| -------------------- | -------- | -------- |
| 串行 + 0.2s 间隔     | 13.6s    | 31.2s    |
| **池化 2 并发**      | **5.9s** | **6.5s** |
| 池化 3 并发          | 24.5s    | 41.2s    |

结论：**2 并发稳定最快**（2–5x）；**3 并发被限流、比串行还慢** —— Wayback 对同客户端
的并发很敏感。生产配置因此显式钉 `web.archive.org: (2, 0.2)`（原来靠 DEFAULT 恰好是 2）。
另：1.5s 暂停（为 Commons 引入）套在 Wayback 上纯属浪费（48 次 × 1.5s = 72s），已去掉。

**整轮增量跑**（同日第二次）：15m32s，产物与上一轮**完全一致**（1544 人 / 1537 有图 /
缺图 7）—— 并发没改变结果 ✓。判据 1 的「≤串行 1/3」按实测订正为 **2–2.5x**（3 并发会
更慢，1/3 在 Wayback 的限流下不可达）。

**另一条订正**：整轮的总时长主要由**网络当时的快慢**决定（今天两次 14m08s vs 15m32s，
数据阶段 2.4 vs 5.6 分钟）—— 单次跑的数字不要当基准，要看阶段拆解。

## 注意

- 并发**只对 I/O 等待**有效；解析与压缩是 CPU 侧，保持主线程串行。
- 结果写回要防竞态：worker 只**收集**（`(成员, url, 证据)`），应用顺序由主线程按确定性规则决定。
- 与工单 05 的心跳配合：心跳要能报「在飞 N 条、已完成 M 条」。
