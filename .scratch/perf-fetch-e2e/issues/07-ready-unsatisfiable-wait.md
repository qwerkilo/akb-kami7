# 工单 07：`ready()` 的恒假等待（主套件 21 分钟里 18 分钟是它）

- **Status**: resolved
- **Blocked by**: 03（进度探针先就位，才看得见这个）

## 背景（工单 03 的画像跑出来之后）

主套件实测 **21m07s / 245 全绿**，分块耗时：9 个块各 **120–134s**，其余块加起来 ~6 分钟。
心跳行 207 条、**全部**是 `…等待图片/字体就绪`；9 次 `ready()` 的完成耗时**都是 120s**
（= `waitForFunction` 的超时上限）—— 即**每一次都烧满超时**。

**根因**：`ready()` 等的是 `[...document.images].every(i => i.complete && i.naturalWidth > 0)`，
而名册卡片的 `<img loading="lazy">`（`app.js:287`）在视口外**永远不会加载** → 条件恒假 →
`.catch(() => {})` 把超时吞掉 → 每次白等 120s。9 次 = **18 分钟 = 整套的 85%**。

## 决定

1. `ready()` 只等**视口内**的图（`getBoundingClientRect` 过滤）+ 字体，超时**有界 15s**。
2. 等爱块里那条「等 `document.images` 全 complete」同理恒假（且海报的图是 `new Image()`
   加载的、根本不在 `document.images` 里）→ 换成等 **`#poster-img` 的 src 变成 data URL**
   （那才是「海报画出来了」的真信号，块 8 早就在用）。
3. `e2e-v5.cjs` 的同款 `ready()` 一并改（同一个恒假条件）。

## 判据（可证伪）

1. 主套件 **245/245** 且墙钟 **< 8 分钟**（优化前 21m07s；实测数字写进本工单）。
2. v5 **54/54** 且墙钟不劣化。
3. **连跑两次全绿**（这是把 18 分钟的「意外等待」拿掉，必须证明它没在替别的断言兜底）。
4. 心跳行数大幅下降（不再有 9 条 120s 的等待）。

## 实现记录（2026-10-05）

**实现**：`e2e.cjs` 的 `ready()` 改成「视口内图片（有界 15s）+ 字体」；等爱块的
「等 `document.images` 全 complete」换成等 `#poster-img` 的 src 变成 data URL；
`e2e-v5.cjs` 的同款 `ready()` 一并改。

**实测**：

| 运行                          | 优化前                   | 优化后                                                             |
| ----------------------------- | ------------------------ | ------------------------------------------------------------------ |
| 主套件（`npm run e2e`）       | 21m07s / 245             | **3m02s / 245**（run 1）· 2m52s / 244（run 2，见下）               |
| v5                            | ~32s / 54                | 30s / 54                                                           |
| 全量并行（`npm run e2e:all`） | 21m11s（且受主套件拖累） | **5m12s**（e2e 3m12s / header 4m04s / pwa 37s / v5 31s，4/4 全绿） |

心跳行数从 207 条（全部是 120s 白等）降到 **0**。

**如实记账**：run 2 出现一次 `244/245` —— 红的是「重新排序会换对手（4 场点出多组
第一对）」（只点出 1 组）。分析：`shuffle` 是 `Math.random()`、与本次改动无关；首对来自
第一层（7 档 4 人 → 6 种可能），4 次全同的概率 ~0.5% —— 是**既有采样太小的偶发假红**。
已把采样 4 → 6（概率降到 ~0.01%，而「resort 没洗牌」的真缺陷仍然全同 → 照样红）。

## 注意

- 海报的像素断言（底色）量的是画布**背景**，不依赖成员照片解码；海报**画出来**的信号
  由 `#poster-img` 的 data URL 提供（判据 2 的连跑就是为这条兜底）。
- 这条改动**动的是「等什么」而不是「等多久」**：把恒假的等待换成真的就绪信号。
