# 40 档「圈内」（v7）spec

**Status:** ready-for-agent

## Problem

32 档并非总选举史实口径（历届圈内为 40/64/80/100，经典口径 40）。用户要求对齐真实口径。

## Solution

档位由 7/16/**32** 改为 7/16/**40**：品牌与芯片文案落在 40 档；旧 32 存档迁移为 40 且保留已选与对决；金字塔行分布 `1-3-5-7-9-11-4`（用户四候选选定）；四样式与 7 人档布局同步修正。

## User stories

1. 档位芯片显示「圈内 40」，选中后托盘 40 格、品牌「圈内」。
2. 40 档对决最坏 177 题（约 15 分钟），进度/续玩/撤回等既有机制不变。
3. 旧 32 档存档打开：已选成员与进行中的对决都还在（继续对决即可）。
4. 40 档海报金字塔为 `1-3-5-7-9-11-4`（7 行，冠军独居塔尖，前 4 行带名字）。
5. 四样式在 40 档均成立：杂志 3×13、榜单领奖台 + 3 栏榜（37 项）、拼贴 8×5。
6. 7 人档下榜单与拼贴不再出现大片空档（榜单余人改一行大字卡、拼贴行块居中）。

## Implementation Decisions

- `core.js`：`SIZES = [7,16,40]`；`deserializeState` 把 `size===32` 映射为 40（其余照旧校验）；`names` 品牌取 `brand_40`。
- `session.js`：`SIZES = [7,16,40]`。
- `i18n.js`：`mode_32`/`brand_32` → `mode_40`/`brand_40`（zh 圈内 40/圈内、en Ranked 40/Ranked、ja 圏内 40/圏内）。
- `index.html`：档位芯片 `data-pick="40"`。
- `poster.js`：金字塔行表 `PYRAMIDS = { 32:…, 40:[1,3,5,7,9,11,4] }`（按成员数取表）；榜单余人 ≤4 时改「一行大字卡」并与领奖台纵向分布；拼贴行块整体居中（小 n 不再出现中缝大洞）；拼贴 40 → 8×5。
- 测试：`worstCase(40)=177`、迁移用例（core + session）、names/fileBase 40、i18n 期望表、四样式 × 7/16/32/40 几何不变量（含 C 领奖台互不重叠）、E2E 走 40 档流程。

## Testing Decisions

- core 缝：迁移、题量、命名；session 缝：迁移后快照；i18n 缝：品牌期望表与真字典；poster 缝：几何不变量；E2E：40 档托盘/品牌/最坏题数/续玩。

## Out of Scope

- 64/80/100 等更大档位；档位并存（32 与 40 同列）；旧 32 存档的「已选保留但不满 40」时的自动补选。
