# 48 Group 扩展：从 AKB48 到国内 7 团

Status: ready-for-agent

## Problem Statement

站点目前的候选池只有 AKB48（含毕业）372 人。其他 48 Group 团体（SKE48、NMB48、HKT48、NGT48、STU48、SDN48）的粉丝无法用同一工具给自家成员排序，也无法跨团混选。

## Solution

把数据管线从单团扩展为国内 6 团 + SDN48（约 1180 人），选人阶段增加「团体」筛选与「团体 → 期生」两级浏览；支持跨团混选与单团神7；兼任/移籍成员按人物去重并标注；无照片成员以占位图参与；结果列表标注团体与期生。

## User Stories

1. 作为访客，我想在选人页看到所有团体的成员，以便跨团选择。
2. 作为访客，我想按团体筛选候选池（全部 / AKB48 / SKE48 / NMB48 / HKT48 / NGT48 / STU48 / SDN48），以便只看某一团。
3. 作为访客，我想在「全部」时按「团体 → 期生」两级浏览，以便理解成员来源与资历。
4. 作为访客，我想在只选一个团体时按该团的期生分组浏览（1期生、2期生……），以便按加入时间找成员。
5. 作为访客，我想用「全部 / 现役 / 已毕业」筛选成员状态，且该筛选作用于所有已选团体范围。
6. 作为访客，我想在分组头上看到人数与现役人数（如「55 人 · 现役 12」），以便了解规模。
7. 作为访客，我想搜索时同时匹配汉字名、假名与昵称，以便用任一种写法找到成员。
8. 作为访客，我想搜索对大小写与变体字（﨑/崎、髙/高、邉/辺 等）不敏感，且片假名输入也能命中平假名，以便输入简便。
9. 作为访客，我想在没有搜索结果时看到清晰提示与建议写法，以便换一种输入。
10. 作为访客，我想点击成员卡片加入候选池，最多 7（或 16）人，以便开始排序。
11. 作为访客，我想在神7 与 16 人版之间切换，两种模式共用同一候选池规则。
12. 作为访客，我想跨团混选成员，以便排出跨团的神7。
13. 作为访客，我想只筛选某团也能完成整场排序，以便玩「单团神7」。
14. 作为访客，我想已选托盘与结果列表显示成员的团体与期生信息，以便确认来源。
15. 作为访客，我想在对决页两两比较并支持撤回，以便修正误点。
16. 作为访客，我想在对决页看到「最多 N 题」进度，以便了解还要点几次。
17. 作为访客，我想结果页显示名次、头像与「团体 + 期生/毕业」信息，以便截图分享时有上下文。
18. 作为访客，我想导出的海报保持现有构图与信息密度（本期不在海报上标注团体）。
19. 作为访客，我想保存海报、分享到 X、以及「这几位重新排序」「重新选人」。
20. 作为访客，我想中英切换时新增的界面文案完整覆盖（zh/en 两套）。
21. 作为访客，我想无照片成员以统一占位图出现且仍可被选择与比较，以便成员不因缺图被遗漏。
22. 作为访客，我想兼任/移籍成员只出现一次（在其归口团体），并标注兼任/移籍来源，以便不重复选到同一张脸。
23. 作为访客，我想首屏不被千余张图片拖慢（缩略图懒加载、收起的分组不渲染卡片 DOM），以便手机上快速开始。
24. 作为维护者，我想用一条命令重新生成成员数据与图片，以便 48pedia 更新后刷新站点。
25. 作为维护者，我想脚本在上游页面结构变化（某行缺图片/缺加入期）时不崩溃并给出提示，以便尽早发现问题。
26. 作为维护者，我想解析器与前端核心逻辑有测试覆盖，以便安全迭代。

## Implementation Decisions

**范围**（见 ADR-0001）

- 纳入 AKB48、SKE48、NMB48、HKT48、NGT48、STU48、SDN48 共 7 个团体，现役 + 毕业全量，约 1178 人。
- 海外姐妹团、Team TP/Team SH、SNH48 系、已解散海外团不纳入；`バイトAKB` 沿用现有排除。

**数据管线**（`fetch_members.py`）

- 抽成可导入的纯函数：按页/节解析（AKB48 现役与元为两页；SKE/NMB/HKT/NGT/STU 为单页「現役メンバー / 元メンバー」两节；SDN48 为单页「在籍 / 最终活动日前毕业」两节，且全部计为毕业）、以及跨团合并去重。
- 图片正则同时接受 `[[ファイル:` 与 `[[File:`（SDN48 与部分 NMB 行使用后者）。
- 期生分组规则泛化到各团（加入期后缀不再是 AKB48 专用），无法归类的进「其他」。
- 保留现有 CLI（默认、`--no-dl`、`--force`）与代理逻辑（`AKB_PROXY`，默认 7897，本机实际用 7890）。
- 重跑时继续清理未被引用的图片文件。

**数据模型**（`members.js`）

- 章节对象增加 `group` 字段，`label` 仅表示期生：如 `{group: "SKE48", label: "1期生", members: [...]}`；成员字段沿用 `id/name/kana/nick/status/end/leave/note/img`。
- 跨团去重（见 ADR-0002）：按「姓名 + 假名」判定同一人物；多条记录按「现役优先、其次最后所属」归口；被合并的来源写入 `note`（如「兼任」「移籍」）；姓名相同但假名不同不合并。
- 无照片成员保留 `img: false`（见 ADR-0003）。

**前端**（`core.js` + `app.js`）

- 抽出无 DOM 依赖的 `core.js`：可回放的归并排序排名引擎与 worstCase、筛选与搜索归一、两级分组构造、占位判断与图片地址选择；`index.html` 在其后加载 `app.js`，由 `app.js` 负责 DOM/交互/海报。
- 选人页新增「团体」筛选（全部 + 7 团，顺序固定 AKB48 → SDN48）；「全部」时两级手风琴（团体 → 期生），单团时单级期生手风琴；现役/毕业筛选与搜索作用于当前候选池；筛选状态不持久化（与现状一致，仅语言持久化）。
- 搜索匹配 `name + kana + nick`：大小写不敏感、片假名归一为平假名、沿用现有汉字变体表。
- 占位图统一用于卡片、已选托盘、对决、结果列表与海报；不得出现破图。
- 文案：`I18N` zh/en 与 `index.html` 的 `data-i18n` 两处同步；标题改为「48 Group 神7 / 48 Group Kami 7」，副标题保留「历代成员版 / All generations」；搜索占位改为「搜索名字（汉字/假名/昵称）」类文案。
- 结果列表 meta 显示「团体 + 期生/毕业」；海报构图不变。

**生成物规模**

- 实际生成 1136 人（跨团去重后）：AKB48 342、SKE48 233、NMB48 210、HKT48 119、NGT48 90、STU48 96、SDN48 46；图片规格不变（full 720×960 q88；thumb 240 q84），约 70MB。
- 45 名历史兼任/移籍者被合并（主要为 AKB48 → SKE48/NMB48/HKT48/SDN48 的转籍者），归入其最后所属团体并在 `note` 标注来源。

## Testing Decisions

- 只测外部行为，不测私有实现：解析器「wikitext 进、成员行出」；`core.js`「数据进、排名/筛选结果出」；产物只断言结构不变量。
- 缝 ① 解析器：Python 标准库 `unittest`，喂固定 wikitext fixture（覆盖：AKB48 双页、普通单页两节、SDN48 两节、`File:` 命名空间、缺图/缺加入期行、跨团同名同假名、同名异假名），不联网。
- 缝 ② 前端核心：`node:test` 覆盖排名引擎（对决序列可回放、worstCase、撤回等价）、搜索与筛选（汉字/假名/昵称、变体字、片假名）、两级分组构造、占位判断。
- 产物不变量：`node:test` 读取生成的 `members.js`，断言 7 个团体齐备、SDN48 全为毕业、每名成员有团体与期生、无重复身份、`img` 为布尔。
- `npm test` 一条命令串联两个 runner；仓库此前无测试，本 feature 建立基建（先落基建再落功能）。

## Out of Scope

- 海外姐妹团（JKT48、BNK48、MNL48、CGM48、KLP48、Team TP、Team SH）、已解散海外团（DEL48、SGO48）与 SNH48 系。
- 运行时抓取或自动更新数据（仍为脚本离线生成后提交）。
- 账号、后端、排名持久化。
- 海报上标注团体（本期不加）。
- 图片规格调整（维持现状）。
- X 以外的社交平台分享。

## Further Notes
