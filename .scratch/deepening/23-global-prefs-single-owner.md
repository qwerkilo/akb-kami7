# ㉓ 全局偏好的单一出处：皮肤 / 海报样式 / 界面语言都归会话

- **日期**：2026-09-29
- **来源**：架构扫描候选 8（唯一剩下的候选）
- **性质**：把已经存在的形状（皮肤）推广到同类偏好，不引入新概念
- **测试缝**：④ `session.js`（往返与校验）+ ③ 文本守卫（键名只有一个家）

## 改前：四种形状

| 偏好       | 形状                                                            | 存储失败时     |
| ---------- | --------------------------------------------------------------- | -------------- |
| 皮肤       | `session.js` 持有 + `read/write`                                | 回默认         |
| 海报样式   | `app.js` 模块变量 + 裸 localStorage，**合法值表在 `poster.js`** | 回默认         |
| 界面语言   | `app.js` 模块变量 + 裸 localStorage                             | 回默认         |
| 已看过标记 | 裸 localStorage **+ 内存 `Set` 回落**                           | 本会话内仍生效 |

前三条的降级其实一致（回默认 ✓），只有第四条**多一层内存回落** ✓ —— 唯一的行为分歧 ✓。

## 改法

1. `session.js` 持有 `lang` / `posterStyle`，导出 `setLang` / `setPosterStyle` ✓，写盘仍走注入的 storage ✓。
2. **合法值表由调用方注入**（`posterStyles: window.AKB_POSTER.styles` ✓）——会话不该知道海报模块有哪些样式 ✓（ADR-0008 的注入式依赖 ✓）。语言同理（`LANGS` 是会话自己的事 ✓，语言集合小且稳定 ✓）。
3. **浏览器语言探测留在 `app.js`**：那是「首次访问选什么」的决定，不是持久化 ✓ → 作为 `opts.lang` 注入 ✓，落盘值优先 ✓。
4. 键名收进 `core.js` 的 `PREF_KEYS` ✓（含 `state: (s) => …` 这个按系列存档 ✓），`session.js` 与 `app.js` 都从它取 ✓。
5. **粘滞标记的内存回落保留，并写清是取舍**：存储不可用时标记只在本会话有效 —— 引导卡不该在同一次会话里反复弹 ✓，而皮肤/语言/海报样式在那种情况下回落到默认值（用户看不出异常 ✓）。已写进 `CONTEXT.md` 的「会话」词条 ✓。

## 守卫（③ 文本守卫 + ④ 行为往返）

- `app.js` 不得出现 `akb` 开头的键名字面量，也不得直接 `localStorage.*("akb…")` ✓
- `session.js` 不得出现 `akb` 开头的键名字面量 ✓
- 两条都必须真的用上 `CORE.PREF_KEYS.*` ✓（否则「一个都不读」也算过 ✓）
- session 侧 7 条新测试：海报样式往返 / 非法值与同值不写盘 / 语言往返 / 落盘恢复与非法值回落 / 存储抛错时不抛且内存里生效 / **注入的默认语言是首屏落点** / 键名单一出处 ✓

## 过程中踩到的两个 bug（E2E 抓的，`npm test` 抓不到）

1. **漏了 `sync()`**：setter 改的是会话的 state，app 的 `snap` 是副本 → 语言切换与海报样式切换**当场不生效** ✓（E2E 95 → 91/95 ✓）。与 `setSkin` 同一形状 ✓，写的时候漏了 ✓。
2. **`opts.lang` 被忽略**：状态里写死 `lang: "zh"` → **日文浏览器首屏落到中文** ✓（v5 E2E 48/49 ✓）。已修 + 补一条测试把注入的默认值钉住 ✓。

诚实记账：两个都是「改完只跑 `npm test` 就提交」的典型漏检 ✓ —— 第一条是三个 E2E 套件之一报出来的 ✓，第二条是另一个 ✓。

（过程记录：第一版守卫的正则只认 `akb:` 前缀，**漏掉 `akb-lang`** → 用变异发现 ✓；又发现「session 写死键名」与「app 某个键不用 PREF_KEYS」都**仍全绿** ✓ → 补了字面量禁令与「至少用上一次」双向守卫 ✓。
