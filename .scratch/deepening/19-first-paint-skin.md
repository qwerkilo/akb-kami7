# ⑲ 首屏不闪皮肤：`:root` 别名必须挂在默认皮肤那一块

- **日期**：2026-09-29
- **来源**：架构扫描候选 2（新访客首屏闪一下贴纸皮肤）
- **性质**：执行 ADR-0011（皮肤）已写下的承诺（`classic`（原版，**默认**）），**不是新决策** → 不新立 ADR
- **测试缝**：E2E 黑盒（`/tmp/opencode/e2e.cjs` 的「首屏不闪皮肤」三条）。**没有**加产物不变式：那条测试会比「CSS 里的选择器名」与「JS 里的默认皮肤字符串」，指不出真实的闪。

## 现象（先建回路再看代码）

回路 `/tmp/opencode/skin-first-paint.cjs`：真浏览器里**只拦 `app.js`**——样式已生效、应用还没 boot，读 `getComputedStyle(document.documentElement)` 的 `--floor` / `--border`；再放开 `app.js` 量稳定后的值。

修复前：

```
首屏·新访客（无 akb:skin）  首屏[(无) #f5f1e6 2px solid #20242e] → 稳定后[classic #edeff3] +279ms ✗ 闪
首屏·已存 sticker          首屏[sticker #f5f1e6 2px solid #20242e] → 稳定后[sticker #f5f1e6] ✓ 一致
首屏·已存 classic          首屏[classic #edeff3 1px solid #d5d9e2] → 稳定后[classic #edeff3] ✓ 一致
```

只有**新访客**闪：已存皮肤的人，`index.html` `<head>` 里的内联脚本会在样式生效前就写好 `data-skin`，所以他们看到的第一帧就是自己选的那款。闪的是奶油底 + 2px 墨描边，闪完翻成浅灰底 + 1px 细边。

**量法说明**：`+279ms` 是用「load 之后注入 `app.js` 再等 `data-skin` 出现」量到的，含一次额外请求，**不是**真实的「首帧 → boot 完成」时长；真实值还要加上 `app.js` 与 `members.js`（376KB）的下载。那个下界没有被证明，所以只把它当量级参考。

## 根因：别名挂错块

`style.css` 里两款皮肤的令牌写在两个块里，`:root`（无属性时的兜底）被**挂在了贴纸块上**：

```css
/* 贴纸（现行风格；:root 兜底与 [data-skin="sticker"] 同值） */
:root,
[data-skin="sticker"] { … }
…
[data-skin="classic"] { … }
```

而应用默认皮肤是 classic（`session.js` 的 `skin: "classic"`）——于是「兜底 = 贴纸」与「默认 = 原版」互相矛盾，新访客必然闪一次。注释里那句「现行风格」是历史遗留：贴纸是本项目自己的风格，但它不是默认值。

## 改法与一个必须记住的坑

改法是**交换两块的位置**并把 `:root` 别名交给原版块：

```css
:root,                     /* 默认皮肤 = 原版 */
[data-skin="classic"] { … }
[data-skin="sticker"] { … }   /* 必须排在原版块之后 */
```

**坑**：`:root` 无条件匹配 `<html>`。第一次改法只把 `:root` 从贴纸块挪到原版块、位置没动，结果**后出现的原版块把贴纸盖掉了**（`data-skin="sticker"` 的人反而变成原版，E2E 掉到 86/89）。同权重下后来者胜，所以「默认皮肤」那一块必须在前面、「选了另一款」的那块在后面。修完：`89/89`。

## 过程中两次自查到的假象（如实记账）

1. **量晚了就不闪了**：先把「稳定后」那一页打开再量「第一帧」，结果全绿——因为应用 boot 会把 `akb:skin` 写进 localStorage，第二页于是读到了已存皮肤。E2E 里必须**先量第一帧再让应用 boot**。
2. **截图骗了我一次**：改完立刻拍的 `first-paint-fresh.png` 仍然是贴纸（与 `first-paint-sticker.png` **md5 完全相同**）。同一分钟重拍就是原版。疑似 `/mnt/sdcard` FUSE 挂载的短暂陈旧读（写完 ~1 分钟内仍供旧内容）——**未证明**。这条也说明：视觉证据必须和计算样式读数一起看，单看截图会得出错误结论。

## 验证

- `npm test`：JS 162 + Python 98 全绿（CSS / index.html 改动不入 node 测试 ✓）
- E2E 回归 **95/95**（新增 9 条，每种情形 3 条：底色 == 本该看到的那款 / `data-skin` == 稳定后 / 按钮圆角 == 稳定后）
- `skin-first-paint.cjs` 绿：三种情形第一帧与稳定后一致
- **像素级证据**（首帧页之间比，布局相同）：新访客首帧 vs classic 首帧 **0.00%**、新访客首帧 vs sticker 首帧 44.41%。注意「第一帧 vs 稳定后」整页比是没意义的——应用 boot 后名册才出现，那测的是「内容出现了」不是「皮肤变了」✓
- 令牌键集：两块各 35 键、集合相同（`python3` 解析 `style.css` 核对 ✓）

## 断言的两次加固（审查指出会假绿）

1. 只比「首屏 == 稳定后」时，**CSS 与应用一起错**也相等——我记录里自曝的「块顺序搞反」那个变异，3/3 全绿。改成同时与「这位访客本来就该看到的皮肤」常量比 ✓。
2. 同一 context 里量第二次会读到应用刚写进 localStorage 的皮肤（我第一次就栽在这，测出来全绿）。改成**两个独立 context** ✓，与顺序无关 ✓。

## 审查打回后补的两条

1. **我引入的回归（已修）**：两个令牌块**键集原本不同**——`--placeholder` / `--placeholder-ink` 只在贴纸块里。原先 `:root` 挂着贴纸块，等于**给 classic 兜了一个「有这个键」的底**；我把别名挪给原版块后，classic 下这四处的 `var(--placeholder)` 全部解析失败，`.card .ph` 背景静默变 `rgba(0,0,0,0)`（缩略图加载期间可见，实测 9.0% 像素差）。已把两键按同值补进原版块，并加注释说明「两块令牌必须键集相同」。
2. **原目标只做了一半（已补完）**：令牌层修好后，**组件层没有**——`style.css` 里 34 处 `[data-skin="classic"] …` 选择器（合并后 26 条规则；含 `.primary` 圆角 999px、`.kami` 字距、`.card` 阴影）没有 `:root` 兜底，于是新访客第一帧是「classic 令牌 + 贴纸时代组件几何」的第三种外观。审查把这题按新事实重开给用户决定（组件规则要不要逐条加兜底），用户选 **A**：`index.html` 的内联脚本在无存储时也显式写 `data-skin="classic"`，让默认皮肤在样式生效前就落到属性上，34 处组件选择器一行不用改。代价是默认皮肤字符串出现在 `index.html` 与 `session.js` 两处 → 由 E2E 的「首屏 data-skin = 稳定后」钉住（`index.html` 写 sticker 而 `session.js` 写 classic 时它会红）。
3. **顺带**：`manifest.webmanifest` 的 `background_color` 原本是贴纸奶油底 `#f5f1e6`，与默认首帧对不上（改前反而是碰巧对的）→ 改成 `#edeff3`。
4. **方案不是最小**：审查实测 `:root:not([data-skin])` 只需改 1 个选择器、与块顺序无关，比「搬 37 行 + 依赖顺序」更稳；记在这里供下一步参考。

## 留给下次的提醒

「默认皮肤的家在 CSS 别名，不在运行时状态」这条原则值得立 ADR，但它是 CSS 与 JS 通用之争、不是本项目特有的决定——真要立会并进皮肤那条 ADR。眼下写在 `style.css` 的注释里（两个块都写了原因），谁把别名挂错块会立刻看出来。
