# ⑳ 指引步数表的单一出处

- **日期**：2026-09-29
- **来源**：架构扫描候选 3（指引步数两个家）
- **性质**：执行 PWA 批次已有的「平台事实」承诺，**不是新决定** → 不新立 ADR
- **测试缝**：i18n 键完整性（`test/i18n.test.js`）

## 现象（先证实再改）

`GUIDE_STEPS`（各平台几步指引）曾写在两个地方：`app.js:1131` 与 `test/i18n.test.js:158`，都是 `{ ios: 4, android: 3, macos: 3, other: 3 }`。

**实测假绿**：把 `app.js` 改成 `ios: 5` → `test/i18n.test.js` **仍然 10/10 全绿**（它拿自己那份 4 去查键）→ 线上会多渲染一条 `t("pwa_ios_s5")` = `undefined` 的空白步骤。`app.js` 里那行注释还特意写着「不给兜底：平台加错了就在这里炸出来」——但表与测试各持一份，这条防线就漏了。

唯一能抓住它的是不入仓的 PWA E2E（`steps === 4` ✓），`npm test` 抓不到。

## 改法

1. `i18n.js` 导出 `GUIDE_STEPS`（它是**文案元数据**：键名 `pwa_<plat>_s<i>` 与步数必须一一对应，住在一起才不别扭），`app.js` 读 `I18N.GUIDE_STEPS` ✓
2. `test/i18n.test.js` 三条测试：
   - 键存在性检查**从表派生**（不重复 ✓），并且**反向查「多出来的文案键」**——步数写小了会有孤儿键 ✓
   - 步数与**文档口径**一致（`{ ios: 4, android: 3, macos: 3, other: 3 }`）。这份副本是有意的**规格声明**：iOS 四步是 `docs/agents/pwa.md` 写着的平台事实（我们更正过一次 Firefox 的事实，就是因为写错没人拦 ✓）
   - **单一出处**守卫：读 `app.js` 源码，断言它引用 `I18N.GUIDE_STEPS` 且不含 `ios: <数字>` ✓。同源文本守卫在本仓已有先例（`test/pwa-artifact.test.js` 守 `skipWaiting` / `mode === "navigate"` ✓）

## 判别力（4 个变异全部变红）

| 变异 | 结果 |
| --- | --- |
| `ios: 4 → 5`（表与文案脱节） | 红 ✓ |
| `ios: 4 → 3`（悄悄少一步） | 红 ✓ |
| `ja` 的 `pwa_ios_s4` 改名成 `s5`（缺键） | 红 ✓ |
| `app.js` 不读 i18n、自持一份（修前形态） | 红 ✓（第 4 条测试就是为它加的） |

诚实记账：**我先把 `i18n.js` 的导出写好、再写测试，所以没见到红**；改用变异证明判别力 ✓，并且第 4 条测试是看到「app.js 自持副本仍全绿」之后才补的 ✓。

## 顺带核对的文档事实

`docs/agents/pwa.md` 只写了「指引按平台分支渲染（`guidePlatform()` + `GUIDE_STEPS`）」，**没有写各平台几步** ✓ → 本轮在那一行补上「步数表住在 `i18n.js`」并由测试钉住（原先它连「表在哪」都没说 ✓）。
