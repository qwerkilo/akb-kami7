# 深化⑰：海报的「照片或占位」收成一个绘制点

来自架构扫描的 Top recommendation（`/tmp/architecture-review-20260929-003318.html` 候选 1）。

## 症状（实测，不是推断）

用假 ctx 跑「全员无照片」（`images: null`）× 四样式 × 三档，统计占位底色的 `fillRect` 次数：

| 样式       | 7     | 16    | 40               |
| ---------- | ----- | ----- | ---------------- |
| a 金字塔   | 7     | 16    | 40               |
| b 杂志     | 7     | 16    | 40（**无首字**） |
| **c 榜单** | **4** | **0** | **0**            |
| d 拼贴     | 7     | 16    | 40（**无首字**） |

c 之所以是 4/0/0：领奖台与紧凑榜行只有 `if (images[i]) cover(…)`、**没有 else**。也就是**40 档选榜单样式、离线出图时，40 张脸里 37 张所在位置什么都不画**（名次与名字还在）。这正面撞上 `CONTEXT.md` 的「离线可用：照片按浏览历史」与 ADR-0016 后果第 2 条。

现有测试**结构上抓不到**：四组海报用例都用 `fakeImgs`（非 null），唯一的占位用例把样式集合写死成 `["a","b","d"]`——等于给 c 立了碑。

## 收口

`poster.js` 新增 `photo(ctx, T, im, box, name)`，五个消费点全部走它：`slotCard`、杂志 hero、领奖台、榜单紧凑榜行、拼贴拍立得。

- 只负责「有图就 `cover`、没图就底色 + 名字首字」；**圆角与裁剪仍归调用点**（拼贴的圆角画在 `rotate` 变换里，搬进 module 就要引入变换感知，接口会变宽而收益没有）。
- 首字字号 `min(框高 / 3, 96px)`：领奖台与 hero 的框高能到 300–700px，直接 /3 会画出 100–233px 的巨字压掉名次角标。
- `box` 用对象而不是四个位置参数：5 个调用点里有一个在 `translate + rotate` 之后用相对坐标，对象让「一个框」这件事读得出来。

## 红回路

- **红**：`test/poster.test.js` 的新测试「全员无照片时每个位置都有占位（四样式 × 三档，占位与首字）」——实现前 `c/7` 报「占位底色应画满 7 格，实际 4」、`d` 报「未用注入的 placeholderInk」。原来那条占位测试里的 `["a","b","d"]` 豁免同时删掉，字色断言从「只有 a」放宽到「每样式都画首字」。
- **绿**：同一条测试四样式 × 三档全绿；`npm test` JS **138** / Python 88。

## 等价性证明

有照片时 `photo()` 只做 `cover`（早退），所以**在线路径的绘制调用序列必须逐条不变**：4 样式 × 3 档的调用条数收口前后完全一致（a 316/703/1686、b 287/674/1706、c 257/299/635、d 4370/6089/5745）。

## 代价与遗留

- **a 样式的占位首字在大卡上收窄了**：7 人档的卡片照片区高约 380px，原来 `/3 ≈ 127px`，现在封顶 96px。视觉核对过：与 hero/领奖台的观感更一致（`/tmp/opencode/ph-check.png` 五张实拍）。这是 Q1 明确批准的封顶，不是副作用。
- **b 的 hero 占位是一大块底色 + 一个 96px 的字**，在 1080 宽的冠军位里略显空。若日后觉得空，把封顶按「框宽的 12%」再调（一个常数）。
- 榜单紧凑榜行的占位首字很小（框高 44px → 15px），但与缩略图尺寸成比例 ✓。
- 假 ctx 仍看不见这些占位的**几何**是否好看（那是候选「海报几何」的范畴，已归档）；本轮靠实拍核对。
