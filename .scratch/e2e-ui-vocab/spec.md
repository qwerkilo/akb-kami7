# Spec：页面操作词汇收口（第六轮扫描候选 ③）

- Status: ready-for-agent
- 来源：第六轮架构扫描候选 ③（Worth exploring）——「页面操作词汇按套件复制，漂移已开始」
- grill：2026-10-07，五问全部采纳推荐（Q1 五个全收 / Q2 统一 300ms / Q3 `_ui.cjs` / Q4 三条守卫 / Q5 两条变异）

## 问题

`e2e.cjs` 与 `e2e-v5.cjs` 各写一份同样的页面操作词汇（只存在于这两个套件）：

| 函数                            | 状态                                                                                    |
| ------------------------------- | --------------------------------------------------------------------------------------- |
| `openFilterPanel`               | **逐字节相同**                                                                          |
| `fillScreening`（划到提交解锁） | **逐字节相同**                                                                          |
| `passScreening`                 | **逐字节相同**                                                                          |
| `openMore`                      | 语义相同、写法分叉（`!(a) \|\| !(b)` vs 两行）                                          |
| `goToPick`                      | **真漂移**：300ms（e2e.cjs）+ if/else vs 250ms（v5）+ 单行 else；两边的注释措辞各写各的 |

「同一约定写两遍、改一处就静默失效」是本仓记录过的坑类；这里的漂移已经发生。

## 决定

| #   | 决定                                                                                                                                                                |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Q1  | **五个全收**（只收三个会把漂移留在原地；pwa 的 `clickCentered`/`pickMembers` 是单拷贝专用，不越界）                                                                 |
| Q2  | `goToPick` **统一 300ms**（取主套件 `e2e.cjs` 的值：两个既有值中更保守、覆盖最多；不引入新魔数）。条件等待（`#phase-pick:not([hidden])`）是行为变更，留待以后单独做 |
| Q3  | 新模块 **`e2e/_ui.cjs`**（与 `_wait`/`_check`/`_progress`/`_suite`/`_playwright` 同族）                                                                             |
| Q4  | 守卫三条：① `_ui.cjs` 的 def 集合 == 五个 ② 套件里不许再定义这五个 ③ 用到就必须从 `./_ui.cjs` 引入                                                                  |
| Q5  | 验收 = `e2e:all` 前后各一次 5/5（245/54/42/72/144 不变）+ 变异两条（抄回 → 守卫红；划除上限 60→0 → 真跑红）                                                         |

## 设计

- `_ui.cjs` 收五个函数（**取 `e2e.cjs` 的 body 为准**，`goToPick` 用 300ms），带原有注释；
  唯一依赖 `./_wait.cjs` 的 `waitForSelector`。
- 两个套件删除本地定义、改成解构引入；各自保留套件专属助手（`openGroup`/`dismissIntro`/
  `checkSecondRound`/`clickFighter` 等）。
- 守卫进 `test/e2e-source.test.js`（套件清单派生自磁盘，与生命周期守卫同源）。

## 验收（可证伪）

1. `_ui.cjs` 的 def 集合 == 五个；两个套件无本地定义、都从 `_ui.cjs` 引入。
2. 守卫三条在迁移后全绿；「把 `fillScreening` 抄回 v5」的变异 → 守卫红。
3. `npm run e2e:all` 前后各一次 **5/5**，check 数 245/54/42/72/144 不变。
4. 变异「`_ui.cjs` 的划除上限 60→0」→ `npm run e2e:v5` 红（行为承重）。
5. `npm run check` exit=0。

## 风险

- 两套件的用法可能有细微差异（同一函数在不同流程里）——迁移时逐调用点核对，跑全量 E2E 验收。
- `openMore` 的两种写法语义等价（短路顺序与返回条件一致：`!(count) || !(isVisible)` vs 两条独立 `if`），合并无行为变化。
