# Spec：E2E 检查记录器（四套件共用一处「记一次检查」）

- Status: ready-for-agent
- 来源：第五轮架构扫描候选 3（`/tmp/opencode/architecture-review-20261006-104242.html`）

## 问题

四个 E2E 套件各写一份「检查记录 + 收尾」：四种收尾行格式（`N/M checks passed` /
`N/M 通过` / `N 项通过，M 项失败` / `全部 N 个状态正常`），`run-all.cjs` 用**四条正则**
反解，`SUITES[].expect` 是计数的**第三份**。同一事实三种表示；改一处格式要同时改
解析与自检。删除测试：合并后四条正则与四种格式整体消失（复杂度集中，不是搬家）。

## 决定（grill 2026-10-06，全部采纳推荐）

| #   | 决定                                                                                                                                                            |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Q1  | **共享记录器** `e2e/_check.cjs`：`createChecker({name})` → `{check, done}`，统一收尾行与 exit code；四套件迁移（header 的「状态」就是一个 check，名字用状态名） |
| Q2  | **数守恒由套件自报**：脚本里声明 `EXPECT`，收尾时自检「数出来的 ≠ 声明值」直接红；runner 删 `expect` 表与 `compareCounts`                                       |
| Q3  | **一次全改**（四套件 + runner + 自检），改完跑 `npm run e2e:all` 验证                                                                                           |
| Q4  | **失败输出统一**：`done()` 打印失败列表 + 追加失败日志（路径 tmpdir 派生，沿用卡 1 的修法）                                                                     |
| Q5  | 收尾行格式 **`[名字] N/M 通过`**（并行日志可读）                                                                                                                |

## 非目标

- 不改各套件的**检查内容**（断言与流程不动）；不改并发/内存策略。
- 不引入新依赖；`e2e/` 仍不进复杂度扫描（已有决定）。

## 验收（可证伪）

1. `run-all.cjs` 里 **`parseCounts` / `compareCounts` / `SUITES[].expect` 消失**（守卫）。
2. 四个套件都走 `createChecker`（守卫：不许自己 `console.log` 收尾行）。
3. **数守恒仍承重**：给某套件删一条 check（变异）→ 该套件**自己**红（EXPECT 自检）。
4. `npm run e2e:all` 4/4 通过、四条命令各自 exit 0；收尾行是统一的 `[名字] N/M 通过`。
5. 失败路径仍出声：注入一条失败 → 失败列表打印 + 失败日志追加（在无 `/tmp/opencode` 的
   环境也不崩）。
