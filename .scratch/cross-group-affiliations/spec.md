# Spec：全部隶属收成一个 `groups`（第六轮扫描候选 ①）

- Status: ready-for-agent
- 来源：第六轮架构扫描候选 ①（Strong）——「48G 转籍者缺席旧团视图：一人多团两套载荷，视图层各认一半」
- grill：2026-10-07，四问全部采纳推荐（Q1-A / Q2-A / Q3-A / Q4 两条都做）
- 领域文档：`CONTEXT.md` 的「移籍」词条已当场更新（元素形状 + 含自家团 + `extras` 退役）

## 问题

同一领域事实（成员的全部隶属）有两个形状、三个层各写一半：

| 层   | 48G/坂道/等爱（`fetch_members.py`）                             | 早安（`morningmusume_members.py`）                      |
| ---- | --------------------------------------------------------------- | ------------------------------------------------------- |
| 产出 | `merge_person` 写 `extras`（**不含自家团**，`{group,current}`） | `_assemble` 写 `groups`（**含自家团**，裸团名）         |
| 投影 | `optional=("bio","leave","note","extras")`                      | `optional=("bio","generation","nick_aliases","groups")` |
| 消费 | 徽标读 `extras`（`core.js:561`）                                | 名册补全 / 搜索读 `groups`（`core.js:377,429`）         |

后果（自复核实测，真实产物）：

- **49 位转籍者缺席旧团名册**：48g 46 人 + 坂道 3 人（柏木由紀 带 `extras=[NMB48,NGT48]`，
  实测不在 NMB48 视图；生駒里奈 `extras=[AKB48]`，不在 AKB48 视图；長濱ねる `extras=[日向坂46]`）。
- 早安 6 位转籍者（嗣永桃子等）名册能补全，但**没有徽标**（badge 只读 `extras`）。
- 守卫把不对称钉成规格：`test/members-artifact.test.js:308` 断言 `withGroups.length === 6`；
  `check_roster.py` 的视图回路只覆盖 `series === "morning"`，48G 缺口正因此不被抓。

## 决定

| #   | 决定                                                                                                                                  |
| --- | ------------------------------------------------------------------------------------------------------------------------------------- |
| Q1  | **统一成 `groups`**：元素 `{group, current}`；48G 的 `extras` **退役**；徽标改读 `groups`（文字里过滤掉自家团）；名册/搜索读 `.group` |
| Q2  | `groups` **含自家团**（「全部隶属」的字面义；早安已是这个形状）                                                                       |
| Q3  | 统一后早安 6 位转籍者**第一次拿到徽标**（「移籍」）—— 接受（同一事实、两个系列同等呈现）                                              |
| Q4  | 守卫改**按系列期望** + 加**视图级抽查**；`check_roster.py` 的视图回路扩到**全部系列**                                                 |

## 设计

- **产出**：48G 侧 `merge_person` 按团归并记录（`current = any(该团记录的 status == current)`），
  `groups` 含自家团；早安侧 `_assemble` 的 `belonged` 升级成 rich。**只在多于一个团时写**
  （单团成员不带字段，两侧一致）。
- **投影**：48G 侧 `optional` 的 `extras` → `groups`；早安侧不变（已有 `groups`）。
- **消费**（`core.js`）：`crossGroupMembers` 与搜索判 `gs.some(g => g.group === 团)`；
  `sourceNote` 读 `m.groups`，文字列「非自家团」的团名，三个分支（兼任/移籍/混在）判据不变。
- **产物**：代码改完须重生成 `members.js`（数据派生，不能手改）；跑增量管线（~15 分钟）。
- **顺带**：`fetch_members.py:328` 的 `not m.get("extras")` 判据改 `groups`（它用「是合并成员」判断要不要补 note）。

## 验收（可证伪）

1. 产物里带 `groups` 的成员 = **morning 6 + 48g 46 + 坂道 3 = 55**；且**0 人带 `extras`**。
2. 视图级抽查（`core.rosterView`，真实产物）：柏木由紀 ∈ NMB48、生駒里奈 ∈ AKB48、長濱ねる ∈ 日向坂46；
   早安 6 人仍在旧团名册（回归）。
3. 徽标：早安转籍者（如 船木結）资料卡出现「移籍」标注；48G 兼任（如柏木由紀）仍是「兼任」；
   文字不含自家团。
4. `check_roster.py` 的视图回路覆盖全部系列；对真实上游跑一遍，11 团口径一致（若有上游口径差异，
   如实记录并订正回路判据，不迁就）。
5. 主 E2E 全绿（名册人数变化处按实测更新期望）；`npm run check` exit=0；复杂度无新增。
6. 变异：①`merge_person` 漏写自家团条目 ②`sourceNote` 文字不过滤自家团 ③搜索不认 `groups` —— 均被杀。

## 风险

- `check_roster` 扩到全系列时，上游（48pedia）可能不把转籍者列进旧团名单 → 假阳性。
  先对真实上游核验口径，再决定回路的判据（不迁就实现）。
- E2E 有多处按团数卡的断言（如 SKE48 / 坂道 / 等爱块），转籍者入册会改计数 → 按实测更新。
