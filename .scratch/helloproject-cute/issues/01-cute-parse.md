`=== メンバー ===` / `=== 過去のメンバー ===`，而℃-ute 的条目是

   （`GROUPS = {"モーニング娘。": {...}, "℃-ute": {...}}`）✓ 不堆第三个布尔 ✓

4. 身高**不进 bio**（决定 3：有就显示 ✓ 但**落哪个键**要定 —— 见下）

## 落地记录（2026-10-02）

### 事实订正三处（都是我在 grill 里说错的）

|        | 我说过的 | 实测                                      |
| ------ | -------- | ----------------------------------------- |
| 规模   | ~24 人   | **8 人**（解散时 5 + 更早 3）             |
| 现役   | 5 人     | **全员毕业**，条目里**没有现役节**        |
| 毕业日 | 有       | 只有「過去に在籍していた」那张表有（3/8） |

`split_rows` 对「没有 `加入期` 列 / 没有毕业日列」的表不报错 ✓ 只是那些字段为空串 ✓。

### 三个真缺口（都是测试抓的）

1. **两个毕业节的列名不同**：`卒業・脱退日（発表日）卒業公演の開催地`（早安）对
   `卒業・脱退日卒業公演会場`（℃-ute）—— 少中间的括号，不归一那 3 人的 end 是日文原文。
2. **「解散時」那张表没有毕业日列** → 那 5 人的 end 必然空 → **必须记 `from_section`**，
   否则下游分不清「源里没有这一列」与「解析失败」。
3. **身高与期生按团不同**：`身長` 只有℃-ute 有（5/8）；`加入期` 两个团都没有 →
   模ーニング娘。的期生来自**官网详情页**而不在这张表里，所以解析层看不到期生是正常的。

### 订正我当初写下的一个设计决定

我曾断言「`height` 不进 member」—— **改**。℃-ute 的源里有身高，而站内身高要出现在
资料卡上（决定 3），所以它必须一路走到成员记录，空串而不是缺键（缺键会让形状断言
变成在测实现细节）。

### 设计上的一个选择值得说

`GROUPS["℃-ute"]["current"]` 是**空列表**，而不是「若无现役节就当全员毕业」。
那样写会掩盖「某个团真的漏了现役节」这种源故障 —— 数据本来的样子是「这个团已解散，
条目里没有现役节」，配置如实反映它。
