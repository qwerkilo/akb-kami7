## 内容

把这一批特有的缺口收口：

1. **「一个系列两个团」的守卫** ✓ —— 现在 `build_sections` 写死一个团 ✓
   加一条产物断言：**早安系列恰好两段 ✓ 且段 label 是那两个团名 ✓**
   与「tab 数 = SERIES_KEYS 键数」那种双向守卫同形 ✓
2. **「已解散团的成员全是毕业」的守卫** ✓ ✓ —— 那是本批最容易静默失效的语义 ✓
   （一旦有人改 `status` 的推导，℃-ute 的人会变成现役 ✓ 而界面上看不出来 ✓）
3. **字段缺失是常态这件事要有守卫** ✓ —— 身高只在一个团有 ✓
   守卫要断言的是「**两个团的字段集可以不同**」✓ 而不是「字段都得齐」✓
   后者会逼着人编数据 ✓
4. **按团的期生**：断言「モーニング娘。有 18 期 ✓ ℃-ute 一期都没有 ✓」✓
   —— 后者不是缺陷 ✓ 是事实 ✓ 钉住它是为了将来有新人加入时不误判 ✓
