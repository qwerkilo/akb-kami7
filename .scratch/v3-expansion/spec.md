# v3 扩展：清空已选、32 人金字塔、成员简介、等爱系列

**Status:** ready-for-agent

## Problem Statement

四个体验缺口：① 选人时想重新开始时只能一个个点掉已选；② 32 人圈内结果图是 8×4 等大平铺，没有名次层级感；③ 成员只有名字/期生/状态一行字，看不到生年月日、出身地等资料；④ 站点只有 48G 与坂道两个系列，缺少指原莉乃制作的等爱系列（=LOVE、≠ME、≒JOY）。

## Solution

- 托盘加「清空」按钮（带确认），一键清除当前系列已选并作废进行中的对决。
- 32 档结果海报与结果页预览改为**金字塔呈现**（A 版 `1-3-5-7-9-7`，行高自上而下递减）。
- 新增**成员简介**：卡片右上角「i」按钮 → 底部资料卡；48G/坂道补「生年月日 + 出身地」（48pedia 表内已有），等爱系列另有「血型/星座/身长/趣味/特技」。
- 新增**等爱系列**（第三系列）：=LOVE 10 + ≠ME 11 + ≒JOY 12 现役、加毕业 4 人，共 37 人；照片按 官网 → Web Archive → Wikipedia/Commons → 占位图 回退。

## User Stories

1. 作为用户，选人时点「清空」并确认后，当前系列已选全部清除，进行中的对决同时作废。
2. 作为用户，已选为空时「清空」按钮不可用（或点击无效果），不会误触。
3. 作为用户，清空只影响当前系列，另一个系列的已选与进度不受影响。
4. 作为用户，32 档结果海报是金字塔式（1 人在塔尖、底行 7 人），名次角标清晰。
5. 作为用户，32 档结果页预览与导出海报完全一致（同一绘制）。
6. 作为用户，7 人与 16 人海报保持现有布局不变。
7. 作为用户，点卡片右上角「i」弹出成员简介（底部资料卡），不干扰点卡片选人。
8. 作为用户，简介显示该成员可用的资料字段（生年月日/出身地/身长/血型/星座/趣味/特技/昵称/团体/期生/状态），无数据的字段不显示。
9. 作为用户，结果列表里也能查看简介（行内 ⓘ）。
10. 作为用户，简介卡可关闭（关闭按钮/点背景/Esc）。
11. 作为用户，能在第三个系列 tab 切换到「等爱」，看到 =LOVE、≠ME、≒JOY 三团（按团体 → 期生两级）。
12. 作为用户，等爱系列的已选、对决进度与海报与其他系列完全隔离（独立持久化）。
13. 作为用户，等爱系列的 7 档叫「推し 7」、海报标签是 `#イコノイジョイ`，标题为「我的等爱 推し 7」。
14. 作为用户，等爱系列也有 32 档（37 人候选池），并用金字塔呈现。
15. 作为用户，等爱系列的毕业成员（佐竹のん乃、齊藤なぎさ、菅波美玲、福山萌叶）在候选池中，照片尽量补（拿不到就占位图）。
16. 作为维护者，等爱数据管线可离线测试（HTML/wikitext fixture + 注入 fetcher），结构变化能被测试挡下。
17. 作为维护者，`members.js` 每个成员带 `bio` 字段（字段随系列不同），产物不变量测试覆盖。
18. 作为维护者，金字塔布局参数化（行分布 + 行高权重），7/16/32 共用同一绘制入口。
19. 作为用户，英文界面下上述所有新文案都有对应英文（zh/en 同步）。
20. 作为用户，有图成员显示照片、无图成员显示占位（现有机制），简介卡在有/无照片时都可用。

## Implementation Decisions

- **清空**：`session.js` 新增 `clearSelection() → bool`（清空 + 作废进行中对决 + 持久化；空时返回 false）；UI 在托盘右侧加「清空」按钮（空时禁用），点击 `confirm` 后清除并重渲染选人页。i18n：`clear_pick` / `clear_confirm`。
- **金字塔（32 档）**：`poster.js` 的 32 布局改为行分布 `[1,3,5,7,9,7]`；行高权重 `1.45 − 0.12i`；格宽 = `min(可用宽 ÷ 行人数, 行高 × 0.86)`（照片 3:4）；行内水平居中；名次角标保留；格宽小于约 118px（1080 画布）时省略名字与字幕。7/16 布局不动。参数化行分布，为将来档位复用。
- **简介数据**：
  - 48pedia 解析新增「生年月日（`{{生年月日|Y|M|D}}`）」「出身地（`{{出身地|…}}`）」两列 → `bio: { birth, from }`。
  - 等爱：官网详情页（血液型/星座/身長/生年月日/出身地/趣味/特技）+ ja.wikipedia（平假名读法、生年月日、出身地、元成员与卒業日、期生）→ `bio: { birth, from, height, blood, sign, hobby, skill }`。
  - `core.js` 新增 `profileRows(m, t, lang)`：把成员可用字段组装为 `[label, value]` 列表（纯函数，node 可测）。
- **简介交互**：卡片右上角小「i」按钮（`aria-label`）→ 底部资料卡（sheet：名字/假名 + profileRows 渲染；关闭按钮/点背景/Esc 关闭）；选人卡片与结果列表共用（结果行加 ⓘ）。不改变「点卡片 = 选中」。
- **等爱系列**：系列 id `love`；系列名 zh「等爱」/ en「=LOVE Family」；三团 =LOVE / ≠ME / ≒JOY；`members.js` 中 `series: "love"`；分组沿用「团体 → 期生」两级。
- **命名模块扩展**：`CORE.names` 支持 love——7 档品牌「推し 7」/ "Oshi 7"；标题前缀「我的等爱」/ "My =LOVE Family"；话题标签 `#イコノイジョイ`；`fileBase` = `love_{size}`；16/32 品牌沿用选拔组/圈内。
- **持久化**：沿用 `akb:state:v2:<series>`（新增 `love`）与 `akb:series`；系列隔离、恢复与校验规则不变。
- **照片回退链**：官网直链 → Web Archive 快照 → Wikipedia/Commons 图 → 占位图；压缩规格与现有图片一致（full 720×960 / thumb 240 宽 WebP），缓存目录沿用 `scripts/_orig/`。
- **管线**：等爱三个官网与 ja.wikipedia 的抓取/解析做成可注入 fetcher 的纯函数（fixture 驱动）；Wikipedia 抓取带重试（实测偶发 SSL 断连）。

## Testing Decisions

- 好测试：只跨接口断言外部行为（选人/清空/切换/绘制可见结果），期望值来自规格与上游样本，不重算实现。
- 缝与用例：
  - **① Python 解析（fixture）**：48pedia 行新增字段（生年月日/出身地）；三官网列表与详情页样本；wikipedia wikitext 样本（现役/元成员/期生/卒業日）；照片回退链（注入 fetcher：官网 200/500 → wayback 命中/未命中 → commons/无 → 占位）。
  - **④ session.js**：`clearSelection` 清空+作废+持久化、空时 no-op、跨系列不影响。
  - **② core.js**：`names` love 变体（brand/title/fileBase/tags，zh/en 穷举）；`profileRows` 字段顺序与缺失字段过滤。
  - **⑤ poster.js（假 ctx + tokens）**：32 金字塔行分布/顺序/角标、行高权重递减、小格省略名字、7/16 布局回归不变。
  - **③ 产物不变量**：love 系列存在、37 人、`bio` 形状、系列与图片/占位标记。
  - **⑦ E2E（/tmp，不入仓）**：清空按钮（确认）、简介 sheet（打开/关字段/关闭）、三系列切换（品牌/标题/标签/文件名）、32 金字塔海报生成无 `undefined`。
- 既有 7/16 海报测试、session 测试、产物测试作为回归基线必须全绿。

## Out of Scope

- 7 人与 16 人海报布局、对决赛制、档位数量不变。
- 等爱系列不单独做专属玩法；毕业成员照片拿不到就是占位图；不建 Web Archive 快照镜像。
- 不新增 =LOVE 家族以外的团体（吉本坂46、坂道研修生等维持排除）。
- E2E 脚本仍不入仓。
