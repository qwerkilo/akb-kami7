# 核心循环改成「清单筛选 → 排序定序」

- **Status**: ready-for-agent
- **日期**：2026-09-29
- **依据**：`docs/adr/0019-screening-then-rank.md`、原型分支 `prototype/ui-v9-duel`（用户选 G）
- **红线**（grill Q4 已确认）：两款皮肤各自的样子、三语言、档位 7/16/40、海报四样式
  与跟随皮肤、E2E 几何断言（可改但要说清为什么）、`core/session/poster` 的模块边界

## 目标

把「两两对决」从唯一核心循环改成**第二步**：先用一屏清单把人数收敛到档位人数
（7/16/40），再对留下的人跑现有的精确全序排序 ✓。顺带修三处实测缺陷：
对决页首屏看不到要选的两张脸、名次角标与「i」按钮挤在同一角、底部托盘 180px 高 ✓。

## 非目标

- 不改皮肤令牌（`test/style-artifact.test.js` 三条不变式守着的 ✓）
- 不改海报四样式与 `poster.js` 的绘制（`defaultTokens()` 等值守卫守着的 ✓）
- 不改 `core.replay` 的排序算法（`mergeSort` 仍是精确全序 ✓）；`worstCase` 仍是
  比较次数的上界 ✓（40 档全排上界 177 题 ✓，但筛选后是 106 题 ✓）
- 不做「锦标赛选边」这类降精度的玩法（原型 F，已判否 ✓）

## 行为规格

### 1 · 筛选步（新增相位 `screening`）

> **本节已被 `docs/adr/0019-screening-then-rank.md` 的改写版取代**（2026-09-29）。
> 初版写的是「筛选到人数 = 档位」，实现后发现不可用：`toggleSelect` 在
> `selected.length >= size` 时拒绝，所以挑人最多选到档位人数，而门槛是
> `kept >= size` → 只有「一个都没划」才能提交。现行语义见下面。

- 从挑人页点「开始」进入**筛选页**（不再有「直接进对决」的旁路 ✓）。
- 一屏列出已选的成员（缩略图 + 名字 + 团体 · 期生 ✓），每人一个「划掉」按钮 ✓。
- **逐轮二分**：每轮必须把保留组划掉一半（定值门槛，超额按钮直接禁用 ✓）；
  保留组剩 4 人即停 ✓。每轮划完是**二选一**：提交 or 点「继续细分」进下一轮 ✓。
- 主按钮在划够前显示「再划 N 人」并禁用；划够后显示「开始排序（约 N 题）」，
  N 是**各层级组大小之和**（7 档 8 / 16 档 27 / 40 档 106）✓。
- 筛选进度可持久化、可续玩 ✓（与对决进度同档 ✓）。
- 键盘/辅助：每行是按钮 ✓，不用拖拽 ✓。

### 2 · 定序步（现有对决，零算法改动）

- 对**每个层级**跑 `core.replayTiers`（`rankTiers` 串起各层级的 `mergeSort` ✓）；
  跨层级不比较 ✓。进度百分比、剩余题数、撤回、保存并返回全部保留 ✓。
- 页头收成一条细进度条：题数 + 进度条 + 「更多」✓（去掉品牌块与步骤条 ✓）。
- 两张脸**垂直居中**、撑满首屏 ✓（并排宽度受 390px 屏限制 ≈160px/张 ✓）。

### 3 · 版面（三项实测缺陷）

- **页头**：品牌 + 系列 + 「⋯」收成一行（实测 66/60px ✓），语言/皮肤进「更多」浮层 ✓。
  档位**留在挑人步** —— 324px 装得下再加档位就 535px > 390px 屏宽 ✓。
- **托盘**：底部一条 ≈72px（缩略图条 + 计数 + 主按钮 ✓），去掉两行说明文字 ✓。
- **卡片**：名次角标移到**左上**、「i」在**右上** ✓，不再挤在同一角 ✓。

### 4 · i18n

- `duel_intro_title/_1/_2/_3` 改写成清单语义（三语 ✓）
- `duel_title` → 筛选页标题（三语 ✓）
- `duel_saved` / `duel_extra` / `undo` / `duel_leave` **继续使用** ✓（排序步）
- 新增：`screen_title` / `screen_keep` / `screen_cut` / `screen_min` /
  `screen_more` / `screen_round`（三语 ✓）
- `screen_intro` 与 `screen_min` 的语义**反转**：`screen_min` 不再是「至少留 N 人」
  而是「再划 N 人」✓
- 死键守卫必须仍全绿 ✓（`test/i18n.test.js` ✓）

### 5 · 测试

- 缝 ② `core.js`：`nav` 认识 `screening` 与新转移 ✓
- 缝 ④ `session.js`：筛选进度往返 / 不足档位被拒 / 两段进度互不覆盖 ✓
- 缝 ⑥ i18n：新键三语齐 + 旧键未被误删 ✓
- 缝 ⑦ E2E：走完「挑人 → 筛选 → 对决 → 出图」✓；断言筛选页文案与两道 CTA ✓
