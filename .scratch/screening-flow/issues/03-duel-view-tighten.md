# 03-duel-view-tighten · 对决页收紧

- **Status**: done
- **所属 spec**：`.scratch/screening-flow/spec.md`
- **依据**：`docs/adr/0019-screening-then-rank.md`

## 内容

页头与步骤条在页内滚动 —— 对决页要滚 2.2 屏才看得到那两张脸。收成一条细进度条
（题数 + 进度 + 剩余），两张脸垂直居中，撤回/保存常驻底部。

**可作回归基线的**：钉住下面的前置状态后，同一构建连跑 3 次取值完全一致 ✓。

前置状态：390×844、7 档、7 人已选、划掉 3 个进对决、关掉说明卡、等图片与字体
加载完（2.5s）。两款皮肤各量一次：

| 量                     | classic | sticker |
| ---------------------- | ------- | ------- |
| 文档高 / 视口高        | 844/844 | 844/844 |
| 两张脸顶边             | 275/278 | 275/278 |
| 两张脸高度             | 290     | 288     |
| 页头 / 步骤条 `hidden` | true    | true    |

**文档高 = 视口高**（844/844）才是可断言的那一条 ✓：整页不滚 ✓，两张脸在首屏 ✓。
E2E 守的也是它 ✓。

**不是基线的**：绝对像素随「选了几个人 / 图片加载进度 / 皮肤」漂 ✓。所以初稿记录的
「改前」两个数只作量级参考 ✓：

| 场景                     | 改前 | 改后 |
| ------------------------ | ---- | ---- |
| 整页文档高（含隐藏相位） | 1350 | 844  |
| 两张脸顶边（同上状态）   | 840  | 275  |

细条复用既有 `duel-step` / `duel-max` / `duel-bar` / `duel-extra` id，所以多数 E2E
断言一行没改。
