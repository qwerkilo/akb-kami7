# Handoff：桌面宽度的两个控件问题（用户报告 2026-10-08）

用户原话：`@diagnosing-bugs pc版页面没有切换语言按钮，同时pc版页面不能选择或者自定义一排有几个头像`

> ① 已修复并推送（见检查点第七十三轮）。② 仍是功能请求，未开工。

## 事实（已核，源码级）

### ① 桌面（>560px）语言切换不可达 —— 真 bug

- `style.css:2009-2011`：`.more-btn { display: none }`（默认隐藏）
- `style.css:2110-2112`：**只在 ≤560px 的媒体查询里** `display: block`
- 语言/皮肤的 seg（`.seg-lang` / `.seg-skin`）**只存在于「更多」浮层内**（`index.html:89-100`，全仓唯一一处 `.seg-lang`）
- ⇒ 宽屏访客没有任何语言切换入口（`openMore()` 也会因按钮不可见而早退，E2E 在桌面宽度下的 `setLang` 会静默跳过）
- **为什么没被测到**：`verify-first-screen` 矩阵是 320–560px、主套件的语言块也在窄屏宽度——**桌面宽度（>560px）从来不在 E2E 覆盖内**（检查点里的长期遗留项）。这是 工单 04「把语言/皮肤收进更多浮层」留下的回归。

### ② 「一排几个头像」不存在这个控件 —— 是功能请求，不是 bug

- 全仓无 `data-cols` / `--cols` / 列数控制（`index.html` / `app.js` / `i18n.js` 零命中）
- 名册列数完全由 CSS 栅格决定（`--card-min` 之类）；用户想要的是**新功能**（桌面自定义每行头像数）
- 按仓库纪律：走**功能链**（grill-with-docs → to-spec → …），不是 `diagnosing-bugs`

## 下一步（按 diagnosing-bugs 纪律）
