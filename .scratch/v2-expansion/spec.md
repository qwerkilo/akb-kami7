# v2 扩展：简体搜索 + 32 档 + 坂道系列 + UI 重做

**Status:** ready-for-agent

## Problem Statement

站点目前只覆盖 48 Group 国内 7 团、只支持 7/16 两档、搜索不认简体字形、界面是初版布局。用户要求四件事：① 简体中文搜索；② 新增 32 人档位（保留 7 与 16）；③ 新增「坂道系列」选项卡，与 48 Group 自由切换；④ 按 UI 技能重做布局与视觉——已先出四款原型并选定 **D · 贴纸网格**（ADR-0007，原型 `prototype/ui-v2@8b74913`）。同时纳入三项架构深化（grill 已确认）：海报绘制 seam、管线路径显式依赖、成员字幕 module。

## Solution

- **数据**：管线新增坂道三团（乃木坂46、櫻坂46、日向坂46），历史成员并入现团、跨团按人物去重；`members.js` 的每个 segment 增加 `series`（`48g` / `sakamichi`）；适配坂道格式（汉字数字期生、`data-sort-value` 日期、`最終在籍日` 列）。
- **搜索**：离线生成「日文形 → 简体形」折叠表（OpenCC，产物文件随数据更新），`core.haystack` 接受折叠表并把折叠形并入 haystack；简体输入（渡边/高桥/马嘉伶）可命中所有写法（渡辺/渡邊）。
- **档位**：7 / 16 / 32；32 档沿用精确全序（最坏 129 题），对决页给出进度百分比与剩余题数/预计时长，并支持退出后继续（localStorage 按系列持久化已选 + 对决进度）。
- **系列**：顶部分段切换；两系列各自保留已选与进度；候选池、搜索、筛选、结果与海报严格限定当前系列；7 人档品牌随系列（48G「神7」/ 坂道「BEST 7」）。
- **UI v2**：按 D 原型重写（不搬运原型代码）：Bento 大小块网格选人、贴纸语言（粗描边/硬阴影/糖果色/微旋转）、移动优先；结果页与海报沿用同一语言。
- **架构**：① 海报绘制抽成接受依赖的 module（成员序列、档位、文案解析、画布目标由调用方传入），布局与字幕获得测试面；② `fetch_members.main` 接受显式目录依赖，测试删除 `patch.object` 自检与真实目录守卫；③ 成员字幕收敛为一个 module（卡片/对决/结果/海报共用，消灭 `m.note` 直用与魔字符串判段）。

## User Stories

1. 作为访客，我能在「48 Group / 坂道」之间切换，两个系列各自保留已选与进行中的对决进度。
2. 作为坂道粉丝，我能浏览乃木坂46 / 櫻坂46 / 日向坂46（含历史成员，按现团归口），并按团体 → 期生两级浏览。
3. 作为中文用户，我能输入简体（如「渡边麻友」「马嘉伶」「宫泽佐江」）并命中日文/繁体写法的成员。
4. 作为用户，我能选择 7 / 16 / 32 档位；32 档时看到进度百分比、剩余题数与预计时长。
5. 作为用户，我中途刷新或关页后回来，能继续未完成的对决（不丢已选与已答题）。
6. 作为用户，坂道侧看到「BEST 7」品牌、48G 侧看到「神7」；海报话题标签随系列（#48Group / #Sakamichi）。
7. 作为用户，选人页是贴纸风 Bento 网格、对决与结果页沿用同一语言，移动端操作顺手。
8. 作为用户，结果与海报字幕不再出现 `undefined`，兼任/移籍成员显示来源与毕业年份。
9. 作为维护者，`fetch_members.py` 的路径依赖显式化（测试不再 patch 全局 + 真实目录守卫），海报与字幕逻辑可在既有 core 缝上测试。
10. 作为用户，32 档海报为 8×4 网格（1080×1440，维持现有规格）。

## Implementation Decisions

- **数据模型**：单文件 `members.js`（YAGNI，不做分文件懒加载）；segment 增加 `series` 字段；坂道期生标签按系列原样展示（48G 阿拉伯数字、坂道汉字数字），排序键用数值；`1.5期|欅坂46` → 标签「1.5期生」。
- **跨团去重**沿用现行规则（姓名+假名，keeper 取现役 > 最晚离团 > 本团；`extras` 记录来源）。
- **折叠表**：管线离线生成（OpenCC `s2t` + `jp2t`），产出 `simplified.js`（`window.AKB_SIMPLIFIED`，形如 `{简: [日文形…]}`），与 `members.js` 同批更新；`core.haystack(member, foldMap)` 接受依赖，测试用夹具表。
- **持久化**：`core` 提供纯序列化函数（serialize/deserialize + 校验），key 形如 `akb:state:v2:<series>`，存 `{size, selected, duel:{order, answers}}`；损坏数据静默丢弃。
- **32 档体验**：进度 = 已答题 / 最坏题数（`worstCase(32)=129`）；预计时长按经验 5s/题估；「剩余最少题数」不做精确下界（Out of Scope），显示剩余最坏题数。
- **UI**：重写 `index.html` / `app.js` / `style.css`（保持无构建、无框架）；贴纸语言设计 token（粗描边 `2px solid #20242e`、硬阴影 `4px 4px 0`、圆角 14-18px、糖果色 peach/mint/lilac/lemon）；海报 canvas 绘制维持 1080×1440、32 档 8×4。
- **架构深化**：
  - 海报绘制 module：入参为（画布/ctx、成员序列、档位、品牌文案、文本解析依赖），`app.js` 仅负责取 canvas、`toDataURL` 与事件。
  - 字幕 module：四类消费（选人卡片、对决、结果列表、海报）共用同一实现；`sourceNote`/`yearLeave` 归入其中。
  - 管线：`main(argv, dirs=…, fetch_page, api_fn, fetch_url)`；模块常量退为 CLI 入口默认值。
- **E2E**：延续现状（脚本在 `/tmp`，不入仓）；新增断言覆盖系列切换、32 档、续玩、海报无 `undefined`。

## Testing Decisions

沿用已确认的三个缝，不新增缝：

- **Python 解析器（fixture 单测）**：坂道页面夹具（汉字数字期生、`data-sort-value` 日期、`最終在籍日`、跨页重复人物）；`main` 显式目录依赖的端到端（无全局 patch）；`--no-dl` 幂等。
- **`core.js`（node:test）**：简体折叠命中（渡边/渡邊/渡辺 → 渡辺麻友；马嘉伶/馬嘉伶）、`haystack` 折叠形、序列化往返与损坏数据、`worstCase(32)=129`、字幕 module 输入输出（兼任/移籍/现役/毕业）、海报 module 布局计算（网格列数、槽位顺序）。
- **产物不变量（node:test 读 `members.js`）**：`series` 字段合法且两组齐全、坂道三团存在、期生标签与排序、无 wikitext 残留、跨团去重无重复身份、字段纯净（沿用现断言并扩展）。
- **E2E 冒烟（Playwright）**：series 切换保留状态、32 档全流程、刷新续玩、海报字幕无 `undefined`、Sakamichi 占位/照片渲染。
- 测试只断言外部行为；期望值来自手推字面量、ADR 规则或上游数据，不重算实现。

## Out of Scope

- 48G 海外团（ADR-0001 不改变）、吉本坂46 与坂道研修生（ADR-0006）。
- 拼音搜索（本轮只做字形折叠；拼音留作后续）。
- E2E 脚本入仓（qa-baseline 遗留项，另行处理）。
- 精确「剩余最少题数」下界算法；分文件懒加载；暗色舞台等其他原型方向的进一步探索。
- 原型代码直接搬运（按原型约束产物重写）。
